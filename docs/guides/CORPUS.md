# The corpus generator

The corpus generator writes documents about a world of the world package (`python/semantic_world/world/`), which embeds a taxonomy of the taxonomy generator and adds fluents, event types with preconditions and effects, and time. The documents are in an artificial language. Every sentence states a proposition about the world, and every proposition is checked true against the world's data before it is written. Every sentence is stored with its words, its parse tree, and its logical form, so we always know what a sentence means and why it is true.

The corpus is a controlled source of language for models. Settings decide which kinds of documents the corpus holds, how the language orders and marks its words, and how ambiguous its surface is. Test sets of matched true and false sentences come with every corpus.

This guide covers running the generator, the ideas behind it, the output files, the test sets, the configuration file, and the Python interface. The design is specified in `docs/specs/CORPUS_GENERATOR.md`, and every design decision is listed in `docs/DECISIONS.md`.

## Quick start

From the root of the repository (see `README.md` in this folder for setup):

```
PYTHONPATH=python python -m semantic_world.corpus generate data/corpus/tiny.yaml
```

The program prints one line:

<!--figure:tiny.corpus.quick_start_block-->
```
wrote runs/corpus/tiny_seed1: 20 documents, 197 sentences, 1043 tokens, 17 scenes, 56 test sets with 633 pairs
```
<!--/figure-->

The tiny corpus is about the tiny world, `data/world/tiny.yaml`: the tiny relations taxonomy (6 categories, 12 instances, 1 scalar dimension, 4 one-place and 4 two-place event types) with 4 Boolean fluents and 2 numeric fluents (`WORLD.md`). It is small enough to read every file by eye. The generator defines the world in memory from its configuration file, so no world run needs to exist first; `world: {run: runs/world/tiny_seed1}` reads a world run instead, and checks it against the regenerated world.

The default corpus is 10,000 documents about the default world, `data/world/default.yaml`:

```
PYTHONPATH=python python -m semantic_world.corpus generate data/corpus/default.yaml
```

It prints <!--figure:default.corpus.wrote_code-->`10000 documents, 100107 sentences, 499852 tokens, 10091 scenes, 56 test sets with 18968 pairs`<!--/figure-->, and takes about 3 minutes (175 seconds) on a laptop (November 4, 2026, stage c5b, with the documents about pair fluents and places and the 56 test sets; the reference run of the same day, from stage c5a's code, took 193 seconds, so the stage added no time; 181 seconds in stage c5a, with the causal statements about pair literals and place event types, against 184 seconds for stage c4c's code the same day; 163 seconds on October 29, 2026, stage c4c, with the initial states, blocked events, descriptions, comparisons, and test items about pairs and places; 164 seconds in stage c4b, with the sentences about pairs and places; 160 seconds in stage c4a, on the default world with its pair fluents and its location fluent; 142 seconds in stages c3b to c2a, 134 seconds in stage c1, 141 seconds in stage b3b, 133 seconds in stage b3a, 158 seconds in stage b2, 157 seconds in stage b1, 158 seconds in stage a8). The world itself takes 8.9 seconds (`WORLD.md`). Every stage records these times, measured with nothing else running, and flags a growth of more than half in its proposal file; there is no hard time limit, and no step is made cheaper by changing what it produces by default (Jon's ruling 3 on stage a8).

Two options change a run without editing the configuration:

- `--seed N` replaces the corpus's master seed. The corpus seed is independent of the world's seed, so the same world can get different corpora.
- `--out DIR` writes the output folder somewhere else. The default is `runs/corpus/<name>_seed<seed>/`.

The example configurations in `data/corpus/` are:

| File | What it makes |
| --- | --- |
| `tiny.yaml` | The tiny corpus above, with 20 pairs per test set. |
| `default.yaml` | The default corpus. Every parameter appears with its default value, so this file is also the reference for defaults. |

## One sentence, four renderings

Every sentence is written four ways. Here is a sentence from a narrative of the tiny corpus (<!--figure:tiny.examples.renderings.label-->`DOC.19.SENT.3`<!--/figure-->): the first sentence that reports an event and whose subject is a definite mention with a relative clause. The four renderings below are of that one sentence, and the script that writes the guides' figures writes them from the tiny run (`python -m semantic_world.figures guides`). The script writes every example of the tiny corpus in this guide. Each example comes from the tiny run's documents or, when no document states one, from the true items of the tiny run's test sets, as the label beside each example shows: a label like `DOC.7.SENT.9` names a sentence of a document, and a label like `class_predicate pair 3` names the true item of a pair of a test set.

| Rendering | The sentence |
| --- | --- |
| Conceptual | <!--figure:tiny.examples.renderings.conceptual-->`THE PROPERTY.4 CATEGORY.2.1 THAT EVENTTYPE2.2.1 THE SCALARDIM.1.LOW CATEGORY.1.1 PLACEEVENTTYPE.1 A PLACECATEGORY.1`<!--/figure--> |
| Formal | <!--figure:tiny.examples.renderings.formal-->`the/LEXEME.62 PROPERTY.4/LEXEME.10 CATEGORY.2.1/LEXEME.5 that/LEXEME.74 EVENTTYPE2.2.1/LEXEME.33 the/LEXEME.62 SCALARDIM.1.LOW/LEXEME.39 CATEGORY.1.1/LEXEME.2 PLACEEVENTTYPE.1/LEXEME.55 a/LEXEME.61 PLACECATEGORY.1/LEXEME.47`<!--/figure--> |
| Propositional | <!--figure:tiny.examples.renderings.propositional-->`{CATEGORY.2.1(REF.1) AND PROPERTY.4(REF.1) AND CATEGORY.1.1(REF.2) AND BELOW(SCALARDIM.1, REF.2, CATEGORY.1.1, 1.0) AND EVENT(SCENE.16.EVENTINSTANCE.1, PAST, PROGRESSIVE, EVENTTYPE2.2.1(REF.1, REF.2))} PLACECATEGORY.1(REF.3) AND EVENT(SCENE.16.EVENTINSTANCE.3, PAST, SIMPLE, PLACEEVENTTYPE.1(REF.1, REF.3))`<!--/figure--> |
| Spelled | <!--figure:tiny.examples.renderings.spelled-->`rau camascuck clonstanzive urs nibuns rau kinen sprost thinic ove osterlal`<!--/figure--> |

In English, with made-up glosses, a sentence of this form says something like "the red owl that was eating the small penguin ran". The main clause reports an event, and the relative clause reports another event of the same scene, which the subject's referent takes part in. The labels show the kinds of the concepts: a `CATEGORY.` label is a category, a `PROPERTY.` label a property, a `PART.` label a part, `SCALARDIM.1.LOW` the low pole of a scalar dimension (small for its category: at least 1.0 standard deviations below the category's mean, a `BELOW` in the propositional rendering), an `EVENTTYPE2.` label a two-place event type, an `EVENTTYPE1.` label a one-place one, and a `PLACEEVENTTYPE.` and a `PLACECATEGORY.` label a place event type and a category of places.

- **Conceptual.** The sentence's words in order, each replaced by its concept's label. The conceptual rendering is a perfectly tokenized version of the language: it has the same word order, morphology, and ambiguities as the spelled rendering, but every word is a symbol for its meaning.
- **Formal.** Each word as its gloss and its lexeme label (`LEXEME.3`). It differs from the conceptual rendering only when synonyms are on, because two synonyms share a concept but are different lexemes.
- **Propositional.** The logical form. Every noun, modifier, and clause becomes its own proposition, joined by `AND`. Referents are labeled `REF.1`, `REF.2`, and so on within each document, so the rendering shows which noun phrases refer to the same thing. The parts in braces are the descriptions, which identify the referents of the definite mentions; the part after them is what the sentence asserts (see "Descriptions and assertions"). The propositional rendering is never ambiguous.
- **Spelled.** The readable spellings of the language's spoken word forms. These come from the word-form pipeline, after the corpus is made (see "Spoken word forms"). Before that, the spelled rendering is empty, and `corpus.txt` holds the formal rendering.

A model can be trained on any of the four. Comparing the conceptual and the spelled renderings isolates the effect of lexical form: the structure is identical, and only the words differ. The propositional rendering removes the language altogether.

## Concepts

### Labels

Labels follow the project's convention: formal labels, indices starting at 1, and periods between indices.

| Object | Label | Example |
| --- | --- | --- |
| Lexeme (a word of the language) | `LEXEME.<n>` | `LEXEME.42` |
| Document | `DOC.<n>` | `DOC.17` |
| Sentence | `DOC.<n>.SENT.<k>` | `DOC.17.SENT.3` is sentence 3 of document 17 |
| Scene | `SCENE.<n>` | `SCENE.8` |
| Event | `SCENE.<n>.EVENTINSTANCE.<k>` | `SCENE.8.EVENTINSTANCE.5` is event 5 of scene 8, in time order |
| Proposition | `PROP.<n>` | `PROP.120`, the same wherever the proposition is said |
| Referent, within one document | `REF.<n>` | `REF.2` is the second thing mentioned in its document |
| Variable, within one sentence | `VAR.<n>` | `VAR.1` in a quantified proposition |

Categories, features, instances, and event types carry the world's labels (`CATEGORY.1.3.2`, `PROPERTY.12`, `PART.4`, `INSTANCE.1.3.2.5`, `EVENTTYPE1.3` for a one-place event type, `EVENTTYPE2.1.2` for a two-place one, and `EVENTTYPE2.1` for a category of two-place event types). A patient capacity is `CANBE.` before its event type (`CANBE.EVENTTYPE2.1.1`: "edible"). A scalar pole is its dimension with `HIGH` or `LOW` (`SCALARDIM.1.HIGH`: "big"). The generic noun "thing" is `THING`, and a function word's concept is its gloss in capitals (`THE`).

The words of phase (c) come after the generic noun, so every earlier content lexeme keeps its label; the function words follow them. A preposition is a content lexeme that takes no affix, so the word-form pipeline needs no change for it. Which pair fluents get a preposition follows from the world: since stage c5b (Jon's ruling 1 of WM.75) every pair fluent the dynamics use, one that some precondition literal or condition literal reads in any form (a pair, `SAME`, `SOME`, or `SOMEOF`, compiled literals included) or that some effect writes; a pair fluent that nothing reads or writes gets none. The prepositions of stage c4b, those of the pair fluents that some literal reads as a pair (the location fluent among them, because every move's compiled literal reads it), stand where that stage put them, and the others are the last content lexemes, after the generic noun for places. Since stage c4c a `SAME` preposition states that two participants have the same partner on its pair fluent (the same place, on the location fluent), and a place pole adjective tells a place apart, describes it, and, in its comparative form, compares two places; the place patient capacities are stated of categories of places since stage c5b ("deserts are reachable"; see "Documents"). A place event type without dynamics (a world with places and no location fluent) has no events and gets no word. `lexicon.named_proportion` has a key for each new type (`pair`, `same`, `place_category`, `place_is`, `place_has`, `place_scalar`, `place_event`, `place_patient_projection`), 1.0 by default and a quarter for the place patient capacities, as for the entities'. Since stage c5a the generic noun for places, `SOMEPLACE`, follows the other words of phase (c) in a world with places ("things that go to places"), and since stage c5b only the prepositions of WM.75 follow it, so every earlier content lexeme keeps its label and its word; a world without places has none.

The language also has 19 function words: `a`, `the`, `all`, `most`, `some`, `no`, `not`, `can`, `is`, `has`, `with`, `without`, `and`, `that`, `it`, `become`, `before`, `than`, and, since stage c5a, `them`, the bound pronoun of a class-level statement (see "Causal statements"). Grammar settings can add more (see "Grammar"), and `lexicon.can_words: distinct` adds `can_now`, a word for what a participant could do at a time point (see "States, changes, and what was possible").

The default world gives <!--figure:default.corpus.lexemes.total|d-->257<!--/figure--> lexemes: <!--figure:default.corpus.lexemes.content|d-->238<!--/figure--> content words and the <!--figure:default.corpus.lexemes.function|d-->19<!--/figure--> function words. One patient capacity in four gets a word (`lexicon.named_proportion.patient_projection: 0.25`). A two-place event type, or a category of them, that is able for every pair of instances, or for none, gets no word, because it says nothing. `stats.yaml` lists such event types under `lexicon.event_types_without_word` (none in the default world). Every fluent gets a state adjective (`lexicon.named_proportion.state: 1.0`); the lexeme tells a state adjective from a static one, because it names a fluent.

Two settings, both 0 by default, add lexical ambiguity. `lexicon.synonym_rate` gives a concept a second word. `lexicon.homonym_rate` makes two words of different concepts share one word form. `lexicon.named_proportion` leaves some concepts without a word, so propositions that need them are never stated.

### Propositions and truth

A proposition is a logical form that the generator checks against the world. There are three levels.

**Class level.** A statement about a category: "most penguins can swim", "penguins are birds", "owls hunt mice". A class-level proposition has a subject category, a predicate, and one of six quantifiers: `nec_all`, `all`, `most`, `some`, `no`, and `nec_no`.

- `nec_all` and `nec_no` are the law-like universals: "all penguins swim" is `nec_all` only when the world's rules fix swimming for every penguin, and "penguins are birds" is `nec_all` because the taxonomy says so. `all` and `no` are the extensional universals: every existing penguin happens to swim. A relation fact ("owls eat mice") and a fact about a subject with a relative clause take the extensional universals only.
- `most` and `some` are judged by the share of the category's instances with the predicate. `most` needs more than half, and a document states it only from 70% (`quantifiers.most.usage_min`). `some` is not stated when the language's universal is true (`quantifiers.some.exclude_all`).
- Which quantifiers the words "all" and "no" state is a setting of the language: `quantifiers.universal_words` is `nec` by default, so "all" means `nec_all`; `extensional` makes it mean `all`, and `either` lets it mean both.
- A bare plural ("penguins swim") states `most` by default (`quantifiers.bare_plural.expresses`), and `nec_all` for a membership fact or a rule statement. The logical form always records the real quantifier, and a sentence's `readings` list the quantifiers that its words allow.
- A document states the strongest true quantifier that the language can state: `nec_all` before `all` before `most` before `some`. In the default language the extensional `all` has no word, so a fact that holds of every penguin without a rule is stated as `most`.
- A scalar pole of a category ("penguins are big") has no quantifier: it says that the category's mean stands at least `scalar_adjectives.z` standard deviations above (or below) the mean of its comparison class, its parent by default, or `ENTITY`, every entity, for a top-level category (see "Comparisons of scalars"). A comparative ("owls are bigger than mice") has none either.

Since stage c5b a class-level statement can be about a category of places: "deserts are dry", "most deserts are reachable" (a place patient capacity), "deserts are places", "deserts are wide" (a place pole, against the parent category of places or `EVERYPLACE`), "deserts are wider than meadows", and, with a category of entities as its subject, "owls can go to deserts" (a place event type with a category of places as its patient, counted over the bindings of an owl and a desert, with the extensional quantifiers). `nec_all` and `nec_no` apply to place properties, place parts, and membership, by the fixed test of the place taxonomy. A predicate about places is never said of a category of entities, nor the reverse, and a category of places is the agent of nothing.

A subject can be restricted: "red penguins", "penguins with fins", "penguins that can swim", "owls that eat mice". A category of places is restricted by place features ("dry deserts"), and takes no relative clause. A restriction narrows the set of instances that the quantifier counts. "Owls that eat mice" are the owls that can eat at least one mouse.

**Causal statements.** What events do and what they need can be stated outright too (see "Causal statements" below): "things that things catch become caught", "things that catch things are awake before". Like rule statements, they are `nec_all`, because the world's definition guarantees them.

**Rule statements.** The world's rules can be stated outright. Each term of a rule's minimal formula is a sufficient condition, stated with the generic noun "thing". Two rule statements of the tiny corpus, each after its label: the first one said with "all", and the first one said with a bare plural (a rule statement that no document states is taken from the true items of the class test sets, and its label names its set and its pair):

<!--figure:tiny.examples.rule_statements.block-->
```
DOC.7.SENT.9  ALL THING WITHOUT PART.3 IS PROPERTY.7
DOC.1.SENT.8  THING WITHOUT PART.1 AND WITHOUT PART.5 THAT IS NOT PROPERTY.1 AND NOT PROPERTY.3 CAN EVENTTYPE1.1
```
<!--/figure-->

A rule statement's quantifier is `nec_all`, said with "all", as in the first line, or with a bare plural, as in the second. A negated PROPERTY feature becomes a relative clause ("that is not red"). A rule statement whose predicate is a one-place event type ("things that are not red can run") states a term of the event type's requirement, which is a rule of the world package over the taxonomy's features. Rule statements are exempt from the limits on sentence length, because rules of every complexity must be stateable. In the default world, <!--figure:default.corpus.rule_statements.stated|d-->88<!--/figure--> of the <!--figure:default.corpus.rule_statements.terms|d-->102<!--/figure--> rule terms are stated. The rest read a scalar threshold, which no adjective states exactly, or have no instance.

**Instance level.** A statement about one instance: "the penguin can swim", "the penguin has stripes", "the penguin is a bird". Truth is read from the instance's own values.

**Event level.** A report that something happened in a scene: "the owl chased the mouse". Every report has a tense and an aspect (simple or progressive), which the logical form always records, even when the language does not mark them. The event itself has no aspect: a document chooses the aspect of each report, at `documents.progressive_rate`, and both aspects are true of an event that happened. The report's grounding says whether the binding is `able` (the world allows it) and `legal` (its preconditions held at some time point of the scene).

**State, change, and `able_now` levels.** Three levels about one participant of a scene at a time point (see "States, changes, and what was possible" below): a state, "the mouse was asleep"; a change, "the mouse became asleep"; and what a participant could or could not do then, "the owl could not eat the mouse". Their truth is read from the scene's history.

Class-level and instance-level propositions can be negative: "penguins can not fly", "no fish have fur". About 10% are, by default (`propositions.negation_rate`). Events are never negated.

### Scenes and events

Narratives need things to happen, so the generator makes scenes. A scene is an episode of the world package. It starts with a seed instance and adds 2 to 6 other instances. Instances that are thematically related to the seed are more likely to join: a scene with an owl tends to have mice in it. Each scene then runs for 3 to 8 time steps. At each step, events are drawn among the events that are legal: the agent, or the agent and the patient, must be able to take part (the world's requirements), and the event type's preconditions on their fluents must hold. An event's effects change fluents, so later events depend on earlier ones, and the history records every change. `scenes.jsonl` holds the histories: each scene's seed, participants, initial fluent values, and the events of every step with their changes. A narrative whose scenes give it nothing to say is drawn again: a scene can have no event at all (the number of events at a step is a Poisson draw), and since stage c4a its events can all be moves and acts at places, which no word reports yet. The new draft takes its scenes from a fresh part of the scene stream, because a scene is drawn from the part named by its number and would otherwise come back the same. `stats.yaml` counts these drafts under `documents.redrawn_drafts`.

Events never contradict the world. Since stage b2 the world's numeric fluents are part of every scene too: a numeric effect moves a participant's value, the drift moves every participant's value at every step, a numeric threshold literal in a precondition decides what is legal, and the history records every numeric change with its cause (`WORLD.md`, "Histories"); since stage b3b the corpus states the numeric fluents (see "Numeric fluents in the language"). Since stage c4a the world's pair fluents and places are part of every scene as well (`WORLD.md`, "Pair fluents" and "Locations"): a scene lists its places (the participants' initial places and `scene.extra_places` more) and each participant's initial place and initial pairs, a pair literal in a precondition (`SAME` on the location fluent, a pair between the participants, `SOME`, `SOMEOF`, or a compiled literal that keeps a profile) decides what is legal, a two-place event's pair effect adds or deletes a pair, and the events of the place event types happen among the entity events: a move takes its agent to another place of the scene, an act happens at the agent's place. The history records every pair change (a move's as the old place deleted and the new one added), and the corpus's truth tests and its independent oracle replay them, so that a derived fluent whose rule reads `SOME` or `SOMEOF`, and every blocked event whose precondition reads a pair, is judged on the right state. Since stage c4b a narrative reports a move or an act as it reports any event, in its turn and in time order, as a transitive verb with the place as its object ("the owl went to the dry place": `EVENT(SCENE.8.EVENTINSTANCE.4, PAST, SIMPLE, PLACEEVENTTYPE.2(REF.1, REF.3))`, the predicate kind `place_event_type`), and a relative clause can report an earlier move or act ("the owl that went to the dry place ate the mouse"). A place is a referent of the document: it is introduced with "a" and mentioned later with "the", numbered among the referents with the entities (`REF.3`), named at a level of the place tree by `mention.place_level_weights` (the leaf heaviest, as for categories of entities), and told apart from the other places of the document's scenes by place properties and parts, by the same incremental algorithm as entities, in a preference order of its own; when the features cannot tell it apart the mention is kept and counted (`stats.yaml`, `mentions.place_definite_not_distinguished`; the tiny place taxonomy's two places of a category share every place property, so none of the tiny corpus's definite place mentions is distinguished). No pronoun refers to a place, a place takes no relative clause, a pair fluent or a location is never a modifier of a mention (it would need a time point), and a place is never the subject of a sentence in phase (c). `scenes.jsonl` holds the place events and the pair changes as before. `scene.extra_places`, `scene.places`, and `scene.initial_location` are the scene settings of places (`WORLD.md`, "The configuration file"). The selection policy is `scene.policy`: `uniform_event` (the default) draws uniformly among the legal events, so an event type that is legal for many bindings is drawn more often; `uniform_event_type` draws the kind of event by `scene.transitive_share`, then the event type, then the binding, as the old scene generator did. `scene.event_type_weights` rebalances the event types under either policy. In the default world, about a third of the events of a scene have a patient (<!--figure:default.world.episodes.two_place_share|.0%-->51%<!--/figure--> of the events of the world's statistics episodes): the world's two-place requirements hold for about a sixth of the ordered pairs of entities and its one-place requirements for about half of the entities, by the retuned settings of `data/world/default.yaml` (see `docs/guides/TAXONOMY.md`, "Where CAN features and verbs went"). `examples/two_place_levers.py` reports how each setting moves the share.

### States, changes, and what was possible

Events change state, and since stage a7a narratives say so. After an event sentence, three kinds of sentence can follow, each at its rate:

- **An initial state.** When an event sentence first mentions a participant, a sentence states one of the participant's fluents at the time point before the participant's first reported event, at `documents.initial_state_rate` (default 0.2): "a mouse was asleep". It is negative ("was not asleep") at `propositions.negation_rate.state` (default 0.1). The proposition is `HOLDS(SCENE.8, TIME.2, PAST, BOOLFL.3(REF.1))`, or `NOT BOOLFL.3(REF.1)` inside for a negative state. Since stage b3b the sentence can state a numeric pole instead, drawn among the Boolean fluents and the numeric poles with words alike: "a mouse was hungry", `HOLDS(SCENE.8, TIME.2, PAST, ABOVE(NUMFL.1, REF.1, RANGE, 0.75))`.
- **A result.** At `documents.result_rate` (default 0.5), a sentence states one change that the event's own effects made in its step to a participant of the event: a base fluent the event changed, or a derived fluent that the event's own changes bring to its new value (since stage b2 an event's numeric changes count among its own changes when a derived fluent that reads a numeric threshold is judged). Since stage b3b a result sentence can state a numeric change the event's own effect made, "the mouse became hungrier", `INCREASE(SCENE.8, TIME.2, PAST, NUMFL.1(REF.1))` (or `DECREASE`): the event's own recorded change moved the value in that direction, and so did the step's net change, the drift included; the proposition says only that the value rose over the step, and a change by drift alone is never a result sentence. "The mouse became awake" is `BECOME(SCENE.8, TIME.2, PAST, BOOLFL.3(REF.1))`: the fluent was false at `TIME.2` and true at `TIME.3`; `BECOME(..., NOT BOOLFL.3(REF.1))` is the opposite change. Since stage c4b (Jon's decision WM.72) a result sentence can also state a pair change of the event's own effects: a pair between two participants that the event added or deleted, the new place of a move, or the loss of the old place, said with `become` and the pair fluent's preposition, "the owl became at the dry place", `BECOME(SCENE.8, TIME.2, PAST, PAIRFL.5(REF.1, REF.3))`, or "the owl became not at the wet place", `BECOME(..., NOT PAIRFL.5(REF.1, REF.4))`. The predicate kind is `pair_state`, with the pair fluent as its label and the second argument, an entity or a place, as its patient, as the timed comparative carries its patient; its truth is read from the replayed pairs as a Boolean fluent's is from the replayed values, and its grounding names the event that recorded the pair change. The same kind states a pair at a time point with the copula, `HOLDS(SCENE.8, TIME.2, PAST, PAIRFL.2(REF.1, REF.2))`, "the owl was near the mouse", which an initial-state sentence states since stage c4c: a participant's place on the location fluent ("a mouse was at a dry place", `HOLDS(SCENE.8, TIME.1, PAST, PAIRFL.5(REF.2, REF.3))`; a negative one names a place already mentioned), its pair with an entity already mentioned, on a pair fluent of which a pair can ever hold (Jon's ruling 3 of WM.76: of a pair fluent with no initial pair and no add anywhere in the world, "the owl was not near the mouse" is always true and teaches nothing, so no initial-state sentence and no state item, true or false, names it; the pair fluent keeps its preposition and its causal statements), or, by Jon's ruling 1 of WM.73, `SAME` with one, "the owl was with the mouse", `HOLDS(SCENE.8, TIME.2, PAST, SAME.PAIRFL.5(REF.1, REF.2))`, true when the two have the same partner on the functional pair fluent, judged from the replayed places; a `SAME` state is never a change. Since stage c4c an event sentence that mentions a place can also be followed, at `documents.place_description_rate` (default 0.1), by a description of the place by its static features, with the place as its subject: a place property or part, a category of places, or a place pole relative to a category of places it is below ("the dry place is wide", `{PLACECATEGORY.1.2(REF.3) AND PLACEPROPERTY.3(REF.3)} ABOVE(PLACESCALARDIM.1, REF.3, PLACECATEGORY.1.2, 1.0)`), as a participant is described at `documents.instance_description_rate`; a place is the subject of such a sentence and of a comparison of places, and of nothing else. A change says nothing of its cause; its grounding records the event whose own effect made it (`caused_by`). An event that changed nothing with a word has no result sentence (since stage b1 an effect whose condition fails changes nothing either). In the default corpus, <!--figure:default.corpus.states.events_with_result_share|.0%-->25%<!--/figure--> of event sentences are followed by a result.
- **A blocked event.** At `documents.blocked_rate` (default 0.1), a sentence says what a participant of the event could not do at that time point: an event type for which the binding is able (the world's requirement holds) and not legal (a precondition fails), "the owl could not eat the mouse", or, since stage c4c, a move or an act at a place of the scene, "the owl could not go to the wet place" (`NOT ABLE_NOW(SCENE.8, TIME.2, PAST, PLACEEVENTTYPE.2(REF.1, REF.3))`); a move to the place the agent is at is never a blocked sentence, because "could not go to where it is" is odd (Jon's ruling WM.53), `NOT ABLE_NOW(SCENE.8, TIME.2, PAST, EVENTTYPE2.1.2(REF.1, REF.2))`. At one minus `propositions.negation_rate.able_now` (default 0.8), the sentence instead says what a participant could do and did not do in that step. `ABLE` holds the static facts fixed, and `ABLE_NOW` the state at a time point too.

Mentions stay static: a definite mention never tells referents apart by a fluent, nor by a pair fluent or a location; a place is told apart by its place properties, parts, and (since stage c4c) poles. States and changes are realized with the copula or `become` and the state adjective, and a pair state or change with the copula or `become` and a prepositional phrase (see "Grammar"); what was possible is said with "can" (`lexicon.can_words: shared`, the default: "can" expresses `ABLE` and `ABLE_NOW` alike, as in English) or with the function word `can_now` (`distinct`). The tense of such a sentence is marked on its auxiliary: as a separate word beside it, or, since stage b3b, as an affix joined to it ("was", "became", "could"), so the word-form request then lists the function words that carry the affix. A sentence's `readings` say `state` for a state or a change, and, with "can" shared, `capacity` and `able_now` for every sentence about an instance with "can". The propositional rendering writes the scene, the time point, and the tense in every case, so it stays unambiguous.

### Causal statements

Every event type of the world has effects, which set base fluents of its participants, and a precondition, which requires fluent values of them. Since stage a7b the corpus states them at the class level, in feature documents:

- **An effect statement.** "Things that things catch become caught": after every event of the event type, the participant in the stated role has the fluent's value. In the logical form, `NEC(ALL(EVENT(EVENTVAR.1, EVENTTYPE2.1.2(VAR.1, VAR.2)), AFTER(EVENTVAR.1, BOOLFL.3(VAR.2))))`: `EVENTVAR.1` binds the events of `EVENTTYPE2.1.2`, `VAR.1` is their agent and `VAR.2` their patient, and `AFTER` says what holds at the time point after the event. An effect that sets a fluent to false is `AFTER(EVENTVAR.1, NOT BOOLFL.3(VAR.2))`, "become not caught".
- **A precondition statement.** "Things that catch things are awake before": `NEC(ALL(EVENT(EVENTVAR.1, EVENTTYPE2.1.2(VAR.1, VAR.2)), BEFORE(EVENTVAR.1, BOOLFL.1(VAR.1))))`, what holds at the event's own time point.

A statement is true exactly when the definition has the entry; a statement about a category of event types ("things that things hunt become caught") is true when every event type below the category has it. Statements are about base fluents only, because the definition guarantees nothing about a derived fluent after an event. Since stage b1 an effect may hold only under a condition (`WORLD.md`, "What a world is"); such an effect guarantees nothing after every event, so the unconditional statement about it is false, and a statement about a category holds only when every event type below it has the entry. Since stage b3b a conditional effect makes a **conditional causal statement**, whose condition joins the restrictor: "red things that things strike become broken" is `NEC(ALL(EVENT(EVENTVAR.1, EVENTTYPE2.1.2(VAR.1, VAR.2)) AND PROPERTY.4(VAR.2), AFTER(EVENTVAR.1, BOOLFL.3(VAR.2))))`, true exactly when every event type below its event type has the effect under that condition, and false without the condition. A static condition is a modifier of the noun phrase of its role (an adjective, a with-phrase or a without-phrase, or "that are not red" in a subject relative), and a fluent condition a `before` predication of a relative clause, `BEFORE(EVENTVAR.1, BOOLFL.2(VAR.1))` in the restrictor ("things that strike things and are awake before", "things that strike things that are asleep before"). A statement about the patient is an object relative, which holds one verb, so a fluent condition or a negated PROPERTY condition of the patient's role has no place in it and such an effect makes no statement; a condition on a numeric threshold is stated only when its threshold is the language's cut, `> cut_high` as the high numeric adjective or `<= cut_low` as the low one, said as a fluent condition is, "hungry things that eat things become full" (`BEFORE(EVENTVAR.1, ABOVE(NUMFL.1, VAR.1, RANGE, 0.75))` in the restrictor, the literal's `cut` in the JSON form), and every other numeric threshold is never stated (decision 23 of the specification, with Jon's exception of October 15, 2026, WM.35); `stats.yaml` counts both kinds of unstated effect. Numeric effects make statements too: `RAISES(EVENTVAR.1, NUMFL.1(VAR.1))` and `LOWERS(...)` say that the event type's effect adds to the numeric fluent, or subtracts from it, "things that eat things become fuller" (`become` with the comparative form of the adjective whose direction it is); they are about the effect, not about the change that was observed, which clamping and drift can hide (decision 28), and a numeric fluent is a topic of feature documents, whose content is the event types that raise and lower it. Since stage c4a the world's event types also carry pair effects and pair literals (`WORLD.md`, "Pair fluents"), which make no statement yet: the statements with pair literals are stage c5a's, a conditional effect whose condition holds a pair literal makes no statement in phase (c) and its unconditional form is never stated as true (Jon's ruling WM.59), and `stats.yaml` counts both kinds among the unstated conditional effects (`pair_condition`, `pair_effect`). Result sentences in narratives are unaffected: they state the changes the history records, which a conditional effect makes only when its condition held. The subject is the generic noun "thing" with a relative clause that names the event: a subject relative for the agent ("things that catch things"), an object relative for the patient ("things that things catch"), and a one-place event type for its agent ("things that sleep"); the other participant is the bare plural "things". An effect's predicate is `become` with the state adjective, and a precondition's the copula with the state adjective and the function word `before`, which stands at the end of the verb phrase or, with `grammar.word_order.before: before_predicate`, at its start. Causal statements are in the present tense and take "all" or the bare plural, by the language's settings for `nec_all`. In the JSON logical form, the subject is `{"head": "THING", "event": "EVENTTYPE2.1.2", "role": "patient"}`, with the `condition` of a conditional statement (`[{"role": "patient", "label": "PROPERTY.4", "value": true}]`), the predicate `{"kind": "effect", "label": "BOOLFL.3", "value": true}`, `{"kind": "precondition", ...}`, or, for a numeric effect statement, `{"kind": "effect", "label": "NUMFL.1", "direction": "raises"}`, and `causal` repeats the definition entry the statement states. A sentence with `become` or `before` and a category as its subject has the reading `causal`.

**Pair literals** (stage c5a, `WORLD_PHASE_C.md`, "Class level"). An effect that adds or deletes a pair, and a precondition literal that requires a pair, its absence, `SAME`, or `SOME`, make causal statements too, compiled literals included. The predicate is a prepositional predicate, and its object is the bound pronoun `them`, which refers back to the other participant of the subject's relative clause:

- "things that approach things become near them": `NEC(ALL(EVENT(EVENTVAR.1, EVENTTYPE2.1.1(VAR.1, VAR.2)), AFTER(EVENTVAR.1, PAIRFL.2(VAR.1, VAR.2))))`. The statement is about the role of the pair's first argument. A delete is "become not near them", and a required pair "are near them before".
- "things that eat things are with them before": `BEFORE(EVENTVAR.1, SAME.PAIRFL.5(VAR.1, VAR.2))`, the two are at the same place.
- "things that grab things are near no things before": `BEFORE(EVENTVAR.1, NOT SOME.PAIRFL.2(VAR.1))`. `SOME` is said with the pair fluent's preposition and a quantified object, the generic noun with `some` or `no` (WM.55). The determiner carries the value, so the verb phrase is never negated. The compiled literal of a functional add is stated so.
- "things that go to places become at them" and "things that go to places are not at them before": the place event types with a verb join the event types of the causal statements, about their agent, with the generic noun for places as their other participant. A move's add and its compiled literal are stated, an act's location literal ("are at them before"), and their Boolean and numeric entries about the agent.

A pair effect or a pair literal on a symmetric pair fluent holds both ways, and so does `SAME`, so the statement about either role is true. Since stage c5b (Jon's ruling 4 of WM.75) the statement is made in one direction only, with the agent as its subject ("things that approach things become near them"); the mirror ("things that things approach become near them"), which the symmetric meaning already carries, stays true and is not stated. `SOMEOF` ("is someone's partner") makes no statement (WM.55). A conditional effect whose condition holds a pair literal makes no statement, and its unconditional form is never stated as true (WM.59); `stats.yaml` counts such effects under `causal.conditional_effects.unstated.pair_condition`. Since stage c5b every pair fluent the dynamics use has a preposition ("The lexicon"), so every pair entry of an event type with a verb can be stated: `causal.pair_entries` counts the pair entries of the definition, those stated, and the others by reason. The default world's definition has <!--figure:default.corpus.causal.pair_entries.effects-->8<!--/figure--> pair effects and <!--figure:default.corpus.causal.pair_entries.precondition_literals-->22<!--/figure--> pair precondition literals, of which <!--figure:default.corpus.causal.pair_entries.stated-->28<!--/figure--> make a statement about their own event type; the language can make <!--figure:default.corpus.causal.statements-->144<!--/figure--> causal statements in all.

**Profile statements** (stage c5a, ruling 5b). A symmetric pair fluent between entities with a preposition gives "things that things are near are near them", `NEC(ALL(PAIRFL.2(VAR.2, VAR.1), PAIRFL.2(VAR.1, VAR.2)))`, and an asymmetric one "things that things are above are not above them", with `NOT` in the scope. The subject's relative clause has the preposition's object as its gap (see "Grammar"). A statement is true exactly when `definition.json` records that symmetry; a general pair fluent, a location fluent, and a functional or total profile make no statement. The JSON predicate is `{"kind": "profile", "label": "PAIRFL.2", "form": "symmetric"}`, the subject `{"head": "THING", "pair": "PAIRFL.2", "role": "second"}`, and the grounding records whether a pair of the fluent can ever hold (`can_hold`). Since stage c5b (Jon's ruling 2 of WM.75) no profile statement is made about a pair fluent that can never hold, one with an initial rate of 0 that no effect of the world adds: its statement would be true of no pair. A profile statement is the first sentence of the document about its pair fluent (see "Documents"), in the section `profile`. The default world gives <!--figure:default.corpus.causal.profile_statements.symmetric-->1<!--/figure--> symmetric and <!--figure:default.corpus.causal.profile_statements.asymmetric-->0<!--/figure--> asymmetric profile statements.

Feature documents state them. A document about an event type, or a category of event types, draws a causal statement at `propositions.causal_statement_rate` (default 0.5) before its other content: what its events do and need. A document about a fluent, a new kind of topic, holds causal statements alone, one per sentence, until it reaches its drawn length or has stated every statement about its fluent: the event types that set it, clear it, and need it. The rate does not apply to a fluent document (stage a8). Narratives keep their result sentences, so the corpus carries both the general statement and its instances. In the default corpus, <!--figure:default.corpus.causal.causal_sentences-->2,669<!--/figure--> sentences are causal statements (<!--figure:default.corpus.causal.effect_sentences-->1,432<!--/figure--> effects and <!--figure:default.corpus.causal.precondition_sentences-->1,237<!--/figure--> preconditions; among the effects, <!--figure:default.corpus.causal.raises_sentences-->127<!--/figure--> `RAISES`, <!--figure:default.corpus.causal.lowers_sentences-->155<!--/figure--> `LOWERS`, and <!--figure:default.corpus.causal.conditional_sentences-->89<!--/figure--> conditional statements); of the default world's <!--figure:default.world.conditional.total|d-->12<!--/figure--> conditional effects, <!--figure:default.corpus.causal.conditional_effects.stated|d-->4<!--/figure--> are stated and <!--figure:default.corpus.causal.conditional_effects.unstated.numeric_condition|d-->0<!--/figure--> have a numeric threshold condition, which no word states; the world has <!--figure:default.corpus.effect_statements|d-->75<!--/figure--> effect statements (59 before this stage, 87 before stage b1). Since stage c5a the statements with pair literals appear where documents already call for causal statements: a document about an event type between entities states its pair literals among its other statements, and a document about a fluent states the place event types that set it or need it (<!--figure:default.corpus.causal.pair_literal_sentences-->585<!--/figure--> sentences with a pair literal and <!--figure:default.corpus.causal.place_event_sentences-->223<!--/figure--> about a place event type in the default corpus). Since stage c5b a document about a pair fluent states the statements about that pair fluent, the location fluent included ("things that go to places become at them"), and a document about a place event type its own; the default corpus holds <!--figure:default.corpus.causal.profile_sentences-->17<!--/figure--> profile statements in its documents.

### Comparisons of scalars

Every scalar dimension of the world gives the language two relative gradable adjectives, one per pole ("big" and "small"). Since stage b3a a pole adjective is a comparison (CG.65): "the big mouse" says that the referent's value on the dimension is at least `scalar_adjectives.z` standard deviations above the mean of its comparison class, the category its noun names, and "penguins are big" that the category's mean is at least that far above the mean of the category's comparison class, its parent by default, or `ENTITY`, the world's symbol for every entity, for a top-level category (CG.3). `scalar_adjectives.class_levels_up` takes the class further up at the class level (2: the grandparent, or `ENTITY` when the tree runs out). The classes are the world's: `derived/comparison_classes.csv` of the world run holds every category's count, mean, and standard deviation on every scalar, and the corpus computes none of its own. In the propositional rendering a pole is `ABOVE(SCALARDIM.1, REF.1, CATEGORY.1.5, 1.0)` or `BELOW(...)`, with the class and the threshold, and a class-level pole compares the mean, `ABOVE(SCALARDIM.1, MEAN(CATEGORY.1.4), CATEGORY.1, 1.0)`; a logical form that holds a pole records the language's threshold under `z`.

A comparative (CG.66) compares two values on one dimension: "the owl is bigger than the mouse" is `GREATER(SCALARDIM.1, REF.1, REF.2)`, the first value exceeds the second, with no class and no threshold, and "owls are bigger than mice" compares two categories' means, `GREATER(SCALARDIM.1, MEAN(CATEGORY.1.2), MEAN(CATEGORY.1.5))`. `GREATER` is the only comparative operator: "the mouse is smaller than the owl" is the same proposition said with the other pole's word, and the sentence's logical form records which word it used (`word`). The grammar has a comparative form of each pole adjective, an affix joined to the adjective by default ("bigger": `grammar.morphology.comparative`, `{realization: affix, position: after}`; `word` makes it a separate function word, before or after the adjective), and the function word `than`, which stands before the object or after it with `word_order.adposition`. A comparative is never negated.

In a narrative, since stage c4c, a sentence that introduces a second place of the scene is followed, at `documents.comparative_rate`, by a comparison of the new place with a place mentioned before, on a place scalar where their values differ ("the dry place is wider than the wet place", `GREATER(PLACESCALARDIM.1, REF.3, REF.4)`); and an event sentence of a two-place event is followed, at `documents.comparative_rate` (default 0.1), by a comparative description of the event's two participants, with the agent as its subject, on a scalar where their values differ or, since stage b3b, on a numeric fluent where their values differ at the event's time point ("the owl was hungrier than the mouse"; see "Numeric fluents in the language"). A category document draws a comparison fact with the same chance as its other kinds of content: the topic compared with one of its comparison partners, on one scalar where the means differ. The partners are the topic's siblings with a word by default (`documents.comparison_partners: siblings`, Jon's ruling on stage b3a); `thematic` gives as many thematic partners instead, the other categories of its level whose leaves are most related to the topic's by the world's thematic relatedness, and `both` gives both, the pool of stage b3a. Every comparison is judged by the world's runtime (`WORLD.md`, "What a world is" and `derived/comparison_classes.csv` under "Reading the outputs"). The two sentences of the tiny corpus below, each after its label, are the first comparative of two entities of a narrative on a scalar and the first comparison fact of two categories of entities: the forms of "the owl is smaller than the mouse" and "owls are bigger than mice", each said with the high pole's word or the low pole's (a comparative that no document states is taken from the true items of the test sets, and its label names its set and its pair):

Since stage c5a (Jon's ruling WM.74) a comparison of two participants, or of two places, uses the compared scalar's poles as modifiers only when its two nouns name different categories. The poles are then relative to different comparison classes, and the sentence does not follow from its own words: "the cold desert is hotter than the hot meadow" is stated when true. Within one comparison class the poles stay out, because "the hot meadow is hotter than the cold meadow" says the comparison twice. When nothing else tells the two mentions apart, the comparison is not made: two mentions are told apart when the noun and the modifiers of one of them do not fit the other's referent. `stats.yaml` counts both under `comparisons`: in the default corpus <!--figure:default.corpus.comparisons.compared_poles_across_classes.participants-->26<!--/figure--> comparisons of participants and <!--figure:default.corpus.comparisons.compared_poles_across_classes.places-->23<!--/figure--> of places use the compared poles across classes, and <!--figure:default.corpus.comparisons.skipped_not_told_apart.participants-->0<!--/figure--> and <!--figure:default.corpus.comparisons.skipped_not_told_apart.places-->0<!--/figure--> were not made. Since stage c5b (Jon's ruling 3 of WM.75) a comparison whose two mentions nothing tells apart is not skipped at once: the other dimensions of the same two arguments are tried first, in a random order (the participants' other scalars and numeric fluents, the two places' other place scalars), because on another dimension the poles of the first one may be modifiers and may tell the two apart. The comparison is made on the first dimension that allows it, and is skipped only when none does. In the default corpus <!--figure:default.corpus.comparisons.made_on_another_scalar.participants-->0<!--/figure--> comparisons of participants and <!--figure:default.corpus.comparisons.made_on_another_scalar.places-->0<!--/figure--> of places were made on another dimension than the one first drawn (`comparisons.made_on_another_scalar`); in the tiny corpus <!--figure:tiny.corpus.comparisons.made_on_another_scalar.participants-->0<!--/figure--> and <!--figure:tiny.corpus.comparisons.made_on_another_scalar.places-->0<!--/figure-->, with <!--figure:tiny.corpus.comparisons.skipped_not_told_apart.participants-->0<!--/figure--> and <!--figure:tiny.corpus.comparisons.skipped_not_told_apart.places-->0<!--/figure--> still skipped. Neither corpus has such a comparison at its size. ### Numeric fluents in the language

Every numeric fluent of the world gives the language two absolute gradable adjectives (stage b3b), one for each end of its range: "hungry" and "full" for a hunger, judged against the ends of the range and not against a comparison class as "big" is (decision 27 of the specification). The high word says that the value is greater than the fraction `numeric_adjectives.cut_high` (default 0.75) of the way through the range, `ABOVE(NUMFL.1, REF.1, RANGE, 0.75)`, and the low word that it is at most `cut_low` (default 0.25), `BELOW(NUMFL.1, REF.1, RANGE, 0.25)`; the high word is strict and the low word inclusive, so that each says exactly what one of the world's numeric threshold literals says, `> t` or `<= t` (Jon's ruling WM.35, October 15, 2026); every proposition with a numeric pole records its cut (`cut` in the predicate), as every proposition with a scalar pole records its z. The adjectives are the concept type `numeric` of the lexicon (`lexicon.named_proportion.numeric`, both poles of a fluent named together), and they take the comparative forms of stage b3a. A numeric fluent changes over a scene, so its adjectives are always said at a time point, never of a category and never as a modifier of a mention:

| Sentence | Propositional rendering |
| --- | --- |
| the owl was hungry | `HOLDS(SCENE.8, TIME.2, PAST, ABOVE(NUMFL.1, REF.1, RANGE, 0.75))` |
| the owl was not full | `HOLDS(SCENE.8, TIME.2, PAST, NOT BELOW(NUMFL.1, REF.1, RANGE, 0.25))` |
| the owl became hungrier | `INCREASE(SCENE.8, TIME.2, PAST, NUMFL.1(REF.1))` |
| the owl became fuller | `DECREASE(SCENE.8, TIME.2, PAST, NUMFL.1(REF.1))` |
| the owl was hungrier than the mouse | `HOLDS(SCENE.8, TIME.2, PAST, GREATER(NUMFL.1, REF.1, REF.2))` |
| things that eat things become fuller | `NEC(ALL(EVENT(EVENTVAR.1, EVENTTYPE2.1.2(VAR.1, VAR.2)), LOWERS(EVENTVAR.1, NUMFL.1(VAR.1))))` |

A state ("was hungry") is said with the copula and the adjective, like a Boolean state, and joins the initial-state sentences of narratives. A change is `become` with the comparative form of the adjective whose direction it is: `INCREASE` says that the value at the next time point is greater than at the time point, whatever moved it (the drift included), and `DECREASE` that it is less; a result sentence states one only when the event's own effect moved the value in that direction and the step's net change has it too, and a change by drift alone is never a result sentence. A comparison of two participants at a time point joins the comparative descriptions of narratives, at the event's own time point, with the word the sentence used under `word` as for a comparative of scalars. `RAISES` and `LOWERS` are the causal statements about numeric effects (see "Causal statements"). A numeric threshold is never stated: no word of the language says "more than three quarters" (decision 23). In the default corpus, narratives hold <!--figure:default.corpus.states.numeric_state_sentences-->579<!--/figure--> numeric states, <!--figure:default.corpus.states.numeric_change_sentences-->1,933<!--/figure--> numeric changes, and <!--figure:default.corpus.comparisons.numeric_comparative_sentences-->595<!--/figure--> numeric comparisons. Every one is judged on the scene's replayed values, by the corpus's truth tests and by the independent oracle of the tests alike. The test sets gain numeric poles in the state sets and the set `state_comparison_role` (see "Test sets").

### Descriptions and assertions

A sentence about instances has two parts (CG.63): the **assertion**, its main clause, and the **descriptions** that identify its referents. In a definite mention ("the furry dog") the noun, the modifiers, and a restrictive relative clause are descriptions; in an indefinite mention ("a penguin") they are asserted, because the sentence introduces the referent; a pronoun has no description. Every mention of the JSON logical form says which it is (`"descriptive": true` or `false`), and the propositional rendering writes the descriptions first, inside braces, then the assertion:

| Sentence | Propositional rendering |
| --- | --- |
| the furry dog has legs | `{CATEGORY.1.3.2(REF.1) AND PROPERTY.12(REF.1)} PART.4(REF.1)` |
| a penguin swam | `CATEGORY.1.3(REF.1) AND EVENT(SCENE.8.EVENTINSTANCE.5, PAST, SIMPLE, EVENTTYPE1.3(REF.1))` |
| it has legs | `PART.4(REF.1)` |

With `renderings.propositional.descriptions: omitted`, the braces and their contents are left out, and the rendering holds the assertion alone. Either way the rendering parses back: the marked form to the full logical form, the omitted form to the logical form with its descriptions removed. The setting changes nothing but the propositional rendering. Whether a description counts as stated, for the `seen` mark of a test item, is `test_sets.seen.descriptions` (default true, which counts everything, as before).

### Documents

The corpus mixes four document types (`documents.mix`):

| Type | Default share | Topic | What it says |
| --- | --- | --- | --- |
| Encyclopedic, category | 30% | A category of entities, or since stage c5b of places | Membership, the category's features, its subcategories' features, and relation facts ("owls eat mice", and the capacity facts about places, "owls can go to deserts", which the document about owls states with its topic as the agent and the document about deserts with its topic as the patient), with contrasts to sibling categories |
| Encyclopedic, feature | 20% | A feature, an event type, or a fluent; since stage c5b also a place property or part, a place event type, or a pair fluent | Which categories have it, which lack it, the rules it takes part in, and what its events do and need (causal statements); a document about a fluent or a pair fluent holds statements alone, one per sentence |
| Entity narrative | 20% | An instance | The instance's features, and the events it takes part in, across 2 to 5 scenes |
| Situational narrative | 30% | A scene | The scene's events in time order, with descriptions of the participants |

Narratives often end early. In the default corpus, about <!--figure:default.corpus.narratives_short.entity|.0%-->41%<!--/figure--> of entity narratives and <!--figure:default.corpus.narratives_short.situational|.0%-->40%<!--/figure--> of situational narratives end before their drawn length, because their scenes run out of events (the follow-up sentences of stage a7a fill some of the length that events alone did not). `stats.yaml` reports the counts.

A category document draws the kind of each sentence (membership, a fact about the topic, a fact about a subcategory, a relation fact, or, since stage b3a, a comparison fact) with the same chance for each kind (`documents.content_kind_weights: equal`). With `proportional`, it draws the kind in proportion to the number of facts of that kind that it can still state; a category has far more relation facts to state than facts about itself, so most sentences of a category document are then relation facts. How a document divides its sentences among kinds of content is a choice of discourse, not a frequency of the world, so the balanced form is the default. A sentence that says "all" of a feature or a capacity states `nec_all` too: a rule fixes the predicate for the category. A subject with an adjective, a with-phrase, or a relative clause is restricted ("all red penguins have fins"): the fact is about the members that the restriction picks out. A sibling contrast follows a fact with the same predicate about a sibling of the topic, with the other polarity, at `documents.sibling_contrast_rate`.

In narratives, an instance is introduced with "a" and mentioned later with "the" or "it". A mention can name an instance by a higher category ("the bird" for a penguin: `CATEGORY.1` for a `CATEGORY.1.1`). When a scene has two things that the noun fits, a definite mention adds adjectives or with-phrases until it picks out one: "the small CATEGORY.1.1" against "the big CATEGORY.1.1", or "the CATEGORY.1 with PART.5 and without PART.6". A sentence with `IS` and a fluent, a numeric pole, or a preposition states a participant's state at a time point (an initial-state sentence), and a sentence with `BECOME` states a result of the event before it (see "States, changes, and what was possible"); the six sentences hold at least one of each. An event sentence can identify a participant with a relative clause that reports another event of the scene, as the sentence of "One sentence, four renderings" does. A sentence like "it can EVENTTYPE2.1 a CATEGORY.1.1", at `documents.instance_description_rate`, is a description of a participant: it can hunt a `CATEGORY.1.1`, said with the category of event types `EVENTTYPE2.1`. A blocked sentence, "the CATEGORY.1.1 can not EVENTTYPE2.1 the CATEGORY.2.2", says what a participant could not do at that time point.

### Grammar

The default grammar is English-like and uninflected: "the penguin swim". The settings in `grammar` change how the same propositions are realized, and never what they say. Changing the grammar changes no logical form and no sentence order.

**Word order.** `grammar.word_order.clause` takes any of the six orders (SVO, SOV, VSO, VOS, OVS, OSV). Two-way settings place determiners, adjectives, with-phrases, relative clauses, adpositions, auxiliaries, and negation before or after their head. Since stage c4b a pair fluent is said with a **prepositional predicate**: the copula (or `become` for a change) and a prepositional phrase, the pair fluent's preposition and a noun phrase, the preposition before the noun phrase (`adposition: preposition`) or after it (`postposition`), as `than` is placed; the prepositional phrase stands where a verb's object stands, so "the owl was near the mouse" is `THE CATEGORY.1.2 IS PAIRFL.2 THE CATEGORY.1.5` in SVO and `THE CATEGORY.1.2 PAIRFL.2 THE CATEGORY.1.5 IS` in SOV. A place event type is a transitive verb whose object is a place mention, `THE CATEGORY.1.2 PLACEEVENTTYPE.2 A PLACECATEGORY.1.2`. In the parse tree the prepositional phrase is a `PP` whose `P` is a content lexeme, beside the `PP` of `than`. The same sentence with `clause: SOV`, `adjective: after`, and `determiner: after`: Since stage c5a the object of a preposition can be the bound pronoun `them` ("become near them") or a quantified generic noun ("near no things"), in a causal statement about a pair literal, where `before` stays at the edge of the verb phrase, after the prepositional phrase ("are near them before"). A profile statement's subject has a relative clause whose gap is the object of a preposition, "things that things are near", and `grammar.word_order.stranding` (WM.58) says where the preposition stands: with `strand` (the default) it stays where the object would stand, alone in its prepositional phrase; with `pied_pipe` it moves to the front of the clause with the relative word, before it (`adposition: preposition`, "things near that things are") or after it (`postposition`). Both settings give correct trees in all six clause orders, and `interpret` reads the preposition in either place. The limits stay: one relative clause per noun phrase, an object relative with one verb or one preposition, and a comparative never in a relative clause.

```
default:   THE CATEGORY.1.2 WITH PART.5 THAT EVENTTYPE1.1 EVENTTYPE1.3
reordered: CATEGORY.1.2 THE WITH PART.5 THAT EVENTTYPE1.1 EVENTTYPE1.3
```

**Morphology.** Number, tense, and aspect are off by default. Each can be turned on, and realized either as an affix or as a separate function word:

```
number and tense as affixes:  ALL CATEGORY.1.1-PLURAL HAVE PART.4
                              THE CATEGORY.1.2 WITH PART.5 THAT EVENTTYPE1.1-PAST EVENTTYPE1.3-PAST
number and tense as words:    ALL CATEGORY.1.1 PLURAL HAVE PART.4
                              THE CATEGORY.1.2 WITH PART.5 THAT EVENTTYPE1.1 PAST EVENTTYPE1.3 PAST
aspect as a word:             THE CATEGORY.1.2 WITH PART.5 THAT EVENTTYPE1.1 PROGRESSIVE EVENTTYPE1.3
```

With number on, verbs agree with their subjects (`number.agreement`), and `is` and `has` become `are` and `have` in the plural. Agreement holds across relative clauses, which creates long-distance dependencies. A word takes at most one affix.

**Ambiguity.** The logical form is never ambiguous, but the surface can be. `grammar.can_rate` gives the share of capacities that say "can". At the class level, it is 0.5 by default, so "penguins can swim" and "penguins swim" both occur. At the instance level, it is 1.0, so "the penguin can swim" always has "can". With the instance rate below 1, and tense unmarked, "the penguin swim" can be a capacity or an event. Each sentence records its possible readings (`readings`), worked out from its words alone, and `stats.yaml` reports how many sentences are ambiguous. Under the default grammar, the only ambiguous sentences are those about an instance with "can", which expresses a capacity (`ABLE`) and what was possible at a time point (`ABLE_NOW`) alike; `lexicon.can_words: distinct` removes the ambiguity with a second word. A class-level sentence also lists the quantifiers its words allow: "all" allows `nec_all` in the default language, and a bare plural allows `nec_all` and `most`.

### `documents.jsonl`

Each document holds its `label`, `type`, `topic`, `scenes`, `referents` (each referent label's instance), and `sentences`. Each sentence holds:

- `label`, `tokens` (lexeme labels), and `words` (word-form labels, after rendering);
- `text`, `formal`, `conceptual`, and `propositional`: the four renderings;
- `tree`: the parse tree, as nested lists. The tree of the sentence <!--figure:tiny.examples.tree.conceptual-->`A CATEGORY.1.1 EVENTTYPE2.1.1 A CATEGORY.2.1`<!--/figure--> of the tiny corpus (<!--figure:tiny.examples.tree.label-->`DOC.9.SENT.1`<!--/figure-->, the first report of a two-place event whose two mentions are a determiner and a noun) is <!--figure:tiny.examples.tree.tree-->`["S", ["NP-SBJ", ["Det", "LEXEME.61"], ["N", "LEXEME.2"]], ["VP", ["V", "LEXEME.31"], ["NP-OBJ", ["Det", "LEXEME.61"], ["N", "LEXEME.5"]]]]`<!--/figure-->. The subject and object are labeled by function, so a tree reads the same in every word order;
- `logical_form`: the proposition as JSON, with its truth `grounding`: how the truth was decided, and the proportion it rests on. The `level` is `class`, `instance`, `event`, `state`, `change`, or `able_now`; a sentence about a time point carries its `scene`, its `time` (`TIME.2`), and its `tense`. A predicate has a `kind` (`property`, `part`, `event_type1`, `event_type2`, `patient_capacity`, `comparison`, `comparative`, `member`, `state`, `effect`, `precondition`, or, since stage c4b, `pair_state` for a pair fluent at a time point or as a change, since stage c4c with a `SAME` label too, and `place_event_type` for an event of a place event type) and names its symbol under `label`; a comparison (a scalar pole, or a numeric pole against `RANGE`) adds its `operator` (`ABOVE` or `BELOW`) and its comparison `class`, and a numeric pole its `cut`; a comparative its `operator` (`GREATER`), its `patient` (the other argument), and the pole adjective the sentence used (`word`); a two-place predicate its `patient`; an effect or a precondition its `value`, or, about a numeric fluent, its `direction` (`raises` or `lowers`); and a numeric change (kind `state` with a numeric fluent as its label) its `direction` (`increase` or `decrease`); and a pair state its `patient`, the second argument of the pair, a mention of an entity or of a place (`{"instance": "PLACE.1.2.1", "referent": "REF.3", "noun": "PLACECATEGORY.1.2", ...}`: a mention of a place has the shape of an entity's, with a category of places as its noun and place features in its restriction). A form that holds a scalar pole adjective anywhere records the language's threshold under `z`. Every mention of a sentence about instances says whether it is `descriptive`. A causal statement's subject is an event term (`head`, `event`, `role`, and the `condition` of a conditional statement), and its `causal` record repeats the definition entry it states. Since stage c5b a class-level subject, or the patient of a class-level relation, may be a category of places (`{"category": "PLACECATEGORY.1", "restriction": ["PLACEPROPERTY.3"]}`); a capacity fact about a place event type has the predicate kind `place_event_type` with such a `patient`; and a profile statement has the subject `{"head": "THING", "pair": "PAIRFL.2", "role": "second"}` and the predicate `{"kind": "profile", "label": "PAIRFL.2", "form": "symmetric"}`, in a sentence of the section `profile`;
- `referents`, `events`, `coreference`, and `distinguished`: for each noun phrase, the thing it refers to (an instance, or since stage c4b a place) and the noun that names it; for each verb, the event it reports, or the time point it is about (`SCENE.8.TIME.2`); and whether each definite mention picks out its referent alone;
- `readings`: the kinds of meaning that the sentence's words allow: its level (`generic`, `capacity`, `event`, `state`, `able_now`, `causal`, or, since stage c5a, `profile`: a class-level sentence whose predicate is the copula with a prepositional phrase), and, for a class-level sentence, the quantifiers.

| --- | --- |
| Class | `class_predicate`, `class_subject`, `class_quantifier`, `class_role`, and law-like twins of the first three; since stage c5b facts about categories of places are among their items |
| Instance | `instance_predicate`, `instance_subject`, `instance_role`, and the comparison sets `instance_comparison_predicate` and `instance_comparison_role` |
| Event | `event_predicate`, `event_subject`, `event_role`, and, since stage c4c, `event_object`, each split into `_possible`, `_blocked`, and `_impossible` |
| State | `state_predicate`, `state_subject`, and, since stage c4c, `state_role` and `state_object`, each split into `_changed` and `_unchanged`, and the numeric comparison set `state_comparison_role` |
| Able now | `able_now_predicate` and `able_now_subject`, each split into `_blocked` and `_impossible` |
| Causal | `causal_effect_<change>` and `causal_precondition_<change>`, with the changes `predicate`, `polarity`, `event`, and `role`, the change `condition` for the effect statements, and a law-like twin of each but the polarity sets; since stage c5b the statements with pair literals and about place event types are among their items |
| Profile (stage c5b) | `profile_predicate`, its law-like twin, and `profile_form` |

The changes are:

- **predicate:** another predicate of the same kind ("penguins can fly" for "penguins can swim");
- **subject:** another subject of the same level;
- **quantifier:** another quantifier ("all" for a "most" fact, or the extensional "all" for a law-like one);
- **role:** agent and patient exchanged ("mice eat owls"), or, for a causal statement, the other role of the event ("things that catch things become caught" for "things that things catch become caught");
- **polarity** (causal statements only): the opposite value ("become not caught");
- **event** (causal statements only): another event type, or category at the same level, that lacks the effect or the literal ("things that things chase become caught");
- **condition** (conditional effect statements only): the statement without its condition ("things that things strike become broken" for "red things that things strike become broken"), which the definition does not guarantee;
- **object** (since stage c4c, Jon's ruling WM.56): the second argument swapped, for a pair, location, or `SAME` state and for an event of a place event type: another referent of the document ("the owl was with the penguin" for "the owl was with the mouse"), or another place the document mentioned ("the owl went to the dry place" for "the owl went to the wet place"); the kind of the second argument is kept;
- **form** (profile statements only, stage c5b): the other form, the asymmetric statement for a symmetric pair fluent ("things that things are near are not near them") and the reverse.

false:  ALL CATEGORY.1.2 HAS PART.6

Three kinds of item have sets of their own:

- **Law-like items.** A false `nec_all` or `nec_no` item whose extensional twin is true: in the pair above, everything the subject names has the predicate, but no rule fixes it, so the item with "all" is false as a law. No observation contradicts such an item, so it tests whether a model grasps lawfulness. These items are in the `_lawlike` sets. The pair above is one.
- **Possible, blocked, and impossible events.** A false event is one that never happened in its document's scenes; since stage c4c the events of place event types are among the items, with the change `object` in place of `role`, which a place cannot fill. It is possible when its binding was legal at some time point of the scene (the requirement and the preconditions held, and the event still did not happen), blocked when the world allows the binding (the agent, or the pair, is `able`) but a precondition never held in the scene, and impossible when the world rules the binding out. A possible false event tests memory of the episode, a blocked one knowledge of the preconditions and the states, and an impossible one can be rejected by world knowledge alone.
- **States.** A state item continues a situational narrative and states a fluent of one of its participants at the scene's final time point, `HOLDS(SCENE.8, TIME.6, PAST, BOOLFL.3(REF.1))`, or, since stage b3b, a numeric pole of one, `HOLDS(SCENE.8, TIME.6, PAST, ABOVE(NUMFL.1, REF.1, RANGE, 0.75))`, or, since stage c4c, a pair state of one: its pair with another referent of the document, its place among the places the document mentioned, `HOLDS(SCENE.8, TIME.6, PAST, PAIRFL.5(REF.1, REF.3))`, or `SAME` with another referent. The false item names another fluent that is false of the referent then (a predicate swap; another numeric pole for a numeric pole, another pair fluent of the same kind for a pair state, never one that can never hold, ruling 3 of WM.76), another participant of which the fluent is false (a subject swap), the arguments of a pair between entities exchanged (a role swap, for a pair fluent that is not symmetric; never for `SAME` or a location), or another referent or place as the second argument (an object swap, WM.56). Each item is marked `changed` when the fluent's value at the final time point differs from its value at `TIME.1` (for a numeric pole, when the pole holds at one of the two time points and not at the other), and a pair whose true or false item changed goes into the `_changed` set: only tracking what the events did can answer it. A pair in `_unchanged` can be answered from the initial state alone. `stats.yaml` gives the share of changed items in each state set (about half in the `_changed` sets of the default corpus). The set `state_comparison_role` compares two participants of a situational narrative on a numeric fluent at the scene's final time point, `HOLDS(SCENE.8, TIME.6, PAST, GREATER(NUMFL.1, REF.1, REF.2))`, and its false item swaps the two.
- **Able now.** An `able_now` item continues a situational narrative and says that a participant could do something at the scene's final time point, `ABLE_NOW(SCENE.8, TIME.6, PAST, EVENTTYPE1.3(REF.1))`, since stage c4c a move or an act at a place the document mentioned among them. A false item is blocked (the binding is able, and not legal then) or impossible (not able), with the same two changes.
- **Causal statements.** A causal item states an effect or a precondition of an event type, and every false item is false under `NEC`: the definition lacks the entry. A false item that held after (an effect) or before (a precondition) every event of its type in the corpus's scenes, of which there was at least one, is marked `observed` and goes into the `_lawlike` twin of its set, as a law-like class item does: no observation contradicts it. A polarity swap is never observed, because the true effect or precondition guarantees the opposite value, so the polarity sets have no law-like twin. Since stage b3b the effect sets hold the `RAISES` and `LOWERS` statements too, whose predicate swap is another numeric fluent and whose polarity swap is the other direction (a numeric statement is observed when every event of its type recorded a change of the fluent in its direction), and the conditional statements, which take one more change, `condition`: the statement without its condition, in `causal_effect_condition`, or in its law-like twin when it held after every event of the type in the scenes. The causal sets are not drawn like the others: every true causal statement of the world is paired with every valid false item of the set's change, so a statement appears in several pairs of a set (stage a8). A set with more than `test_sets.size` such pairs keeps a draw of them stratified by statement (stage b1): the pairs of each statement are shuffled, and the set takes one pair from each statement in turn, round after round, until it is full, so that every statement appears before any appears twice, and every statement of the set is kept as long as there are no more statements than the size. Both items of a pair record the true statement they test, under `statement` (its propositional rendering) and under `statement_record` (its causal record with its `kind`, `effect` or `precondition`), so that an analysis can group a set's pairs by statement; `stats.yaml` counts the distinct statements of each causal set (`true_statements`). Since stage c5a the corpus also states causal statements with pair literals and about place event types; the causal sets keep to the statements of the earlier stages until stage c5b, which adds them with the profile sets and a role swap that skips symmetric pair fluents.
- **Pair literals, places, and profiles** (stage c5b). The causal sets hold the statements with pair literals and about place event types. A predicate swap of a pair literal keeps its kind: another pair fluent with a preposition, another `SAME` preposition, or `SOME` of another pair fluent. An event swap of a statement about a place event type brings in another place event type. The role swap gives no item for a place event type, nor for a symmetric pair fluent or `SAME`, whose swapped statement is the mirror and is true (WM.41 and WM.75). The `observed` mark of such an item reads the replayed pairs of every scene. A profile item states a profile of a pair fluent, and its sets are enumerated as the causal sets are: `profile_predicate` says the same form of another pair fluent between entities with a preposition that lacks the profile, and `profile_form` the other form of the same pair fluent. A false profile item is marked `observed`, and goes into `profile_predicate_lawlike`, when its form held of every pair at every time point of every scene of the corpus and some time point held a pair of the pair fluent; the other form is never observed, so `profile_form` has no law-like twin. A class item about a category of places takes the swaps of any class item, within the kind of thing: another category of places of its level, another predicate about places of its kind; a capacity fact about a place event type takes no role swap.
- **Comparisons.** An instance comparison item continues a narrative document and compares two of its referents on a scalar, `GREATER(SCALARDIM.1, REF.1, REF.2)`, said with the "bigger" word or the "smaller" word, drawn with equal chances for the pair (both items use the same word; the greater argument is the subject of "bigger" and the object of "smaller"). The false item swaps the scalar for one on which the comparison is false (`instance_comparison_predicate`; a world with one scalar has none) or swaps the two arguments (`instance_comparison_role`). The class-level comparison facts ("owls are bigger than mice") join `class_predicate` and `class_role` with the same two changes, and the poles of categories ("penguins are big") take the predicate and subject swaps of the class sets.
- **Items in context.** An instance-level, event-level, state, or `able_now` item names a narrative document, and is tested as a continuation of it. "The penguin" in the item refers to that document's penguin.

Each item has two parts. `input` holds what a model sees: the document it continues, the sentence's tokens, renderings, tree, and logical form. `meta` holds the answer and the bookkeeping: `truth`, the change, the grounding, `possible` for events, `law_like` for class-level items, `changed` and `changed_item` (which item of the pair changed: `true_item`, `false_item`, `both`, or null) for state items, `observed`, the `causal` record, `statement`, and `statement_record` for causal items, and `seen`. An event item's aspect is drawn for the item, and its false item keeps it. True and false items never differ in the format of `input`, so the format never gives the answer away.

**Seen and unseen.** True test items are not held out of the documents. Instead, `seen` records whether an item's proposition appears in any training document. A false item is never seen. Scoring seen and unseen items separately tells memory apart from generalization. A report counts as seen in either aspect. ## Spoken word forms

The corpus is made first, in symbols. The word-form pipeline then makes a spoken word for every lexeme, and `render` attaches the words to the corpus:

```
PYTHONPATH=python python -m semantic_world.corpus generate data/corpus/tiny.yaml
PYTHONPATH=python python -m semantic_world.wordforms all data/wordforms/corpus_tiny.yaml
PYTHONPATH=python python -m semantic_world.corpus render runs/corpus/tiny_seed1 --wordforms runs/wordforms/corpus_tiny_seed1
```

`generate` writes `wordform_request.yaml`: the lexemes with their parts of speech, the function words in order of their frequency in the corpus, the affixes the grammar needs (by default one, the comparative of the pole adjectives, scalar and numeric, which every adjective's word must be able to take), the inflected forms the documents use (with the tense as an affix, those of the auxiliaries too, `{function_words: [is, become], affixes: [PAST]}`), and the categories' meaning vectors. The word-form pipeline reads the request, makes pseudowords, assigns them to lexemes, and synthesizes them. `render` fills the spelled rendering, `corpus.txt`, the word columns of `lexicon.csv`, and the word-form run's identity in `config.yaml`. It changes nothing else in the corpus run.

For the tiny corpus, the three steps take under a minute (about 6 to 10 seconds for the word forms with audio and embeddings, 2.6 seconds for `generate`, and under a second for `render`). Since stage c5b the tiny corpus has 60 content lexemes and `data/wordforms/corpus_tiny.yaml` makes exactly 60 words: the count is kept, because a larger count changes the words the earlier lexemes get. Using `forms` in place of `all` makes the word forms without audio, which is all that `render` needs. The rendered tiny corpus has <!--figure:tiny.corpus.tokens|d-->1043<!--/figure--> tokens. For the default corpus, `data/wordforms/corpus_default.yaml` is the matching word-form configuration: it reads the request in `runs/corpus/default_seed1`, and writes `runs/wordforms/corpus_default_seed1`; its <!--figure:default.corpus.lexemes.content|d-->238<!--/figure--> content lexemes (the prepositions and the places' words among them since stage c4b) and <!--figure:default.corpus.lexemes.function|d-->19<!--/figure--> function words, with the comparative affix and its eight inflected forms (the four scalar poles and the four numeric poles), take about 30 minutes with audio and all five embeddings the first time (30 minutes on October 15, 2026, stage b3b; 31.5 minutes in stage b3a; 5.6 minutes on October 29, 2026, stage c4b, when the word forms were remade for the 236 content lexemes of the corpus with its sentences about pairs and places, the audio cache of the earlier run holding the clips of 203 of them; 28.8 minutes the same day in stage c4c, when they were remade again because the request's inflected forms gained the comparatives of the four place pole adjectives, which the comparisons of places use, with every lexeme keeping its word; 34.0 minutes on November 4, 2026, stage c5a, when they were remade for the new function word `them` and the new content lexeme `SOMEPLACE`, with every earlier lexeme keeping its word; 6.5 minutes the same day in stage c5b, when they were remade for the preposition of the pair fluent `PAIRFL.2` (WM.75), every clip read from the audio cache and every earlier content lexeme keeping its word), and `render` about 3 seconds.

The word-form pipeline decides how sound relates to meaning: arbitrary, correlated at a target, marked by branch, or shaped by features. Its guide, `WORDFORMS.md`, covers this under "Assigning words to meanings" and "Word forms for a corpus". The words a lexeme gets never depend on the number of documents or the test sets, so a corpus can grow without its words changing.

## The configuration file

`data/corpus/default.yaml` lists every parameter with its default. A configuration file only needs the parameters it changes: `tiny.yaml` sets the world, the document count, and the test-set size, and nothing else. Unknown keys are errors, and every error names the file and the field. A key of the old corpus (`taxonomy`, `quantifiers.all_grounding`, `scene.verb_weights`, and the others renamed in stage a5a) is an error that names the new key.

## Using the generator from Python

```python
from semantic_world.corpus import load_config, config_from_mapping, generate

config = load_config("data/corpus/tiny.yaml", seed=1)
corpus = generate(config)
corpus.write()                       # writes runs/corpus/tiny_seed1/

document = corpus.documents[5]
document.type, document.topic        # ('situational', 'SCENE.4')
sentence = document.to_json()["sentences"][14]
sentence["conceptual"]               # 'THE SCALARDIM.1.LOW CATEGORY.1.1 BECOME BOOLFL.2'
corpus.stats["ambiguity"]            # the ambiguity counts of stats.yaml
corpus.planner.world                 # the corpus's view of the world (semantic_world.corpus.World)
corpus.planner.world.result          # the WorldResult of the world package behind it
```

`config_from_mapping` builds a configuration from a dictionary, which is convenient for sweeping a parameter:

```python
import yaml

settings = yaml.safe_load(open("data/corpus/tiny.yaml"))
settings["grammar"] = {"word_order": {"clause": "SOV"}}
corpus = generate(config_from_mapping(settings))
```

`generate(config, world)` also takes a `World` that is already in memory, from `load_world(config)`.

## Recipes

- **A taxonomic corpus.** Only encyclopedic documents, with no relation facts: `documents.mix: {encyclopedic_category: 0.6, encyclopedic_feature: 0.4, entity: 0, situational: 0}` and `documents.relation_fact_share: 0`.
- **A thematic corpus.** Only narratives: `documents.mix: {encyclopedic_category: 0, encyclopedic_feature: 0, entity: 0.5, situational: 0.5}`.
- **A verb-final language.** `grammar.word_order: {clause: SOV}`. Add `adjective: after` and `relative_clause: before` for a more consistently head-final language.
- **Agreement and long-distance dependencies.** `grammar.morphology.number: {enabled: true}`, with `mention.relative_clauses: {rate: 0.3, max_depth: 2}`.
- **An English-like morphology.** Number with `verb_marks: singular` ("the penguin swims", "penguins swim"), and tense as an affix.
- **An ambiguous surface.** `grammar.can_rate: {class: 0.5, instance: 0.5}`, with tense and aspect unmarked. In the tiny corpus, 54 of the <!--figure:tiny.corpus.sentences|d-->197<!--/figure--> sentences then allow both a capacity and an event reading (a run of October 10, 2026, with the rates changed; the count is not regenerated with the guide's other figures). `ambiguity` in `stats.yaml` gives the count.
- **Symbols only.** Train on `corpus_conceptual.txt` or `corpus_propositional.txt`, and skip the word-form pipeline.
- **The extensional universals.** `quantifiers.universal_words: extensional`, for a language in which "all" means every existing instance. The `nec` quantifiers are then stated only by the bare plurals of membership facts and rule statements, which no observation can make law-like, so the law-like test sets are empty.
- **The old scene generator's draws.** `scene.policy: uniform_event_type` on a world with `fluents: {count: 0}` gives scenes with the participants of the corpus's old scene generator, with the kind of event drawn by `scene.transitive_share`.

## Troubleshooting

- **"quantifiers.weights.no: is written none".** YAML reads a bare `no` as the boolean false. In `quantifiers.weights`, the quantifier "no" is written `none`, and `nec_no` is written `nec_none`.
- **"taxonomy: is now world".** The corpus is about a world of the world package. Point `world.config` at a world configuration file (`data/world/default.yaml`), which names the taxonomy.
- **"scene.event_type_weights.EVENTTYPE2.1: not an event type".** A category of event types takes no weight: weight its event types.
- **"entities.csv differs from the regenerated world".** A run folder given as `world.run` is regenerated from its `config.yaml` and compared. Regenerate the run with the current code, or point the corpus at the world's configuration file instead.
- **"grammar.morphology.number.on: is now enabled".** The morphology switch is `enabled`. YAML reads a bare `on` as the boolean true.
- **A document shorter than its range.** Narratives end when their events run out, and encyclopedic documents end when they have nothing more to say. `stats.yaml` reports drawn and achieved lengths for each type.
- **A small test set.** A world can run out of true items for a set. `stats.yaml` reports the number of pairs in each set.
- **"the run was not made from this corpus's request".** `render` needs a word-form run made from this corpus's own `wordform_request.yaml`. A corpus generated again with other settings needs a new word-form run.
- **Too few words.** The word-form pipeline stops when its configuration makes fewer content words than the corpus has content lexemes. The default corpus has <!--figure:default.corpus.lexemes.content|d-->238<!--/figure--> content lexemes.
- **Relative paths.** Paths in a configuration are read from the folder the command runs in. Run from the root of the repository, as the examples do.
