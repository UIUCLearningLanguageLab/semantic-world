# The world package

The world package defines a world and runs it. A world is a set of entities with fixed features, a set of fluents that change over time, and a set of event types that say what can happen to the entities and what each event changes. The package generates a world from a taxonomy of the taxonomy generator, writes the world's definition as data files, runs episodes of the world, and writes their histories. The corpus generator reads worlds and writes documents about them. The 3D engine will later read the same definition files.

This guide covers running the package, what a world is, the commands, the output files, the configuration file, the default world's figures, the conformance fixtures, the two-place share, and the Python interface. The design is specified in `docs/specs/WORLD_AND_LANGUAGE.md` and, for phase (c), `docs/specs/WORLD_PHASE_C.md`, and every design decision is listed in `docs/DECISIONS.md` (WM.1 to WM.71, and the engineering choices WM.E1 and following).

## Concepts

### What a world is

A world definition has three parts: the entities' base facts, the feature rules, and the event types. Nothing else is part of the definition. What a model sees, and what the language names, are settings of the experiment and of the language.

- **Entities** are the instances of the embedded taxonomy, `INSTANCE.1.3.2.5`. Each has a leaf category, free PROPERTY and PART features, and scalar values. These are its **base static facts**: stored, and fixed for the life of the world. Its **derived static facts**, the determined PROPERTY and PART features, are computed from them by the taxonomy's rules and never stored as inputs.
- **Fluents** are Boolean facts that change over time, `BOOLFL.1` to `BOOLFL.n`. A **base fluent** is stored, starts at an initial value for each entity, and changes when an event's effect writes it. A **derived fluent** is computed by a rule that reads at least one fluent, and may read static features too, and, since stage b2, numeric threshold literals (`NUMFL.1 > 0.75`); it is recomputed at every time point and never written. So every fact is static or fluent, and base or derived.
- **Numeric fluents** (stage b2) are real-valued facts that change over time, `NUMFL.1` to `NUMFL.n`, as a need rises and is met. A numeric fluent is a base fluent with a **range** (`[0, 1]` by default) to which its values are clamped, an **initial distribution** from which each entity's starting value is drawn when the world is generated (`uniform` over the range, `fixed` at a value, or `beta` with a mean and a concentration), and a **drift**: a change at every step, by itself, which half of the numeric fluents get by default. A **numeric effect** adds a constant to a numeric fluent of a participant or subtracts one, `patient.NUMFL.1 += 0.3`. Every real the world draws and stores (a drift, an initial value, a numeric effect's constant) is rounded to 4 decimals when drawn, as the scalar thresholds and comparison margins are, so that the same seed gives the same world on an ARM and an x86 machine (stage c1, Jon's ruling WM.60); a fixed initial value is the configuration's own. A **numeric threshold literal** compares a numeric fluent with a point of its range, `agent.NUMFL.1 > 0.75` or `agent.NUMFL.1 <= 0.75`, and can stand in a precondition, in a condition, or in a derived fluent's rule. Within a step each numeric value becomes `clamp(clamp(v + e) + d)`: the one effect that wrote it, then the drift, each clamped to the range, in float64.
- **Comparisons** (stage b2) are judged on demand, never stored: `GREATER(SCALARDIM.1, x, y)` (strict: two equal values give false both ways), `ABOVE(SCALARDIM.1, x, K, z)` and `BELOW` (at least `z` standard deviations above, or below, the mean of the comparison class `K`, a category or `ENTITY`, the symbol for every entity), with entities or category means (`MEAN(CATEGORY.1.4)`) as arguments. On a numeric fluent, at a time point, `ABOVE(NUMFL.1, x, RANGE, q)` says that the value is greater than the fraction `q` of the way through the range and `BELOW` that it is at most that point (`ABOVE` is strict and `BELOW` inclusive, so the two are the world's numeric literal `> t` and its negation `<= t`; Jon's ruling WM.35, October 15, 2026), and `INCREASE` and `DECREASE` that it rose or fell over a step. `derived/comparison_classes.csv` holds every category's count, mean, and standard deviation on every scalar.
- **Event types** are the kinds of thing that can happen. A **one-place event type** (`EVENTTYPE1.4`) has one role, the agent. A **two-place event type** (`EVENTTYPE2.1.2`) has an agent and a patient; two-place event types form a tree, and a category of the tree (`EVENTTYPE2.1`) is a more general kind of event, as "hunt" is to "chase". A **binding** assigns entities to the roles, never the same entity twice.
- **The requirement** of an event type is a rule over the static facts of a binding. When it holds, the entities are **able** to take part: the owl can eat the mouse. Capacities ("can") are requirements. A one-place requirement is a rule over the agent's features, sampled as the taxonomy's rules are. A two-place requirement is the conjunction of constraints over both roles, which can compare the two entities' scalars (the agent is bigger than the patient) or match their features (barbers cut hair).
- **The precondition** is a conjunction of fluent literals over the binding, `agent.BOOLFL.2 AND NOT patient.BOOLFL.5`, and, since stage b2, numeric threshold literals, `agent.NUMFL.1 > 0.75`. It says whether the event can happen now: the owl is awake, and hungry enough. A binding is **legal** in a state when its requirement holds and its precondition holds in that state. A share of the precondition literals (`event_types.preconditions.numeric_share`, 0.3 by default) is numeric when the world has numeric fluents; every numeric literal is achievable, by some entity's initial value, by the drift, or by some effect.
- **The effects** set base fluents of the participants, `patient.BOOLFL.3 := 1`, or, since stage b2, add a constant to a numeric fluent or subtract one, `patient.NUMFL.1 += 0.3` (a share of the effects, `event_types.effects.numeric_share`, 0.3 by default). An event type never has two effects that write the same fluent of the same role, never a Boolean effect that sets a fluent to the value its own precondition requires, and (since stage c4a, Jon's ruling WM.70) never a Boolean effect `:= v` on a fluent that can never be `not v`: a fluent whose initial rate is 1 (or 0) and that no effect anywhere in the world sets false (or true), so that the effect could never change the state. The generator draws such an effect again (an inherited one is dropped), as it draws again a delete on a pair fluent that can never hold (Jon's ruling 1 on stage c2b), in the fix-up rounds until stable; an event file's effects are what the file says. Since stage b1 an effect may carry a **condition**, `when patient.PROPERTY.4 AND patient.BOOLFL.2 then patient.BOOLFL.3 := 1`: a conjunction of one or two literals over the binding, each a static feature (PROPERTY or PART, free or determined), a Boolean fluent (base or derived), or, since stage b2, a numeric threshold (`agent.NUMFL.1 <= 0.5`) of one role. The condition is judged in the state at the start of the step, before any effect of the step; when it is false, the effect does nothing. A condition never bears on whether the event is legal. A share of the effects (`event_types.effects.conditional_share`, 0.2 by default) gets a condition when the world is generated; with the share at 0 the world is the unconditional world, byte for byte.
- **Time.** An episode has time points `TIME.1`, `TIME.2`, and so on. Step k takes the state at `TIME.k` to the state at `TIME.k+1`. Every event of a step must be legal at `TIME.k`, and the events of one step must not interfere: no two write the same fluent of the same entity (every effect counts as a write, whatever its condition; a numeric effect writes its numeric fluent), and none writes a fluent that another's precondition, or a condition of another's effect, reads (a condition on a derived fluent reads every base fluent the derived fluent depends on, numeric fluents read through thresholds included; a condition on a static feature reads nothing an event can write). The effects whose conditions hold are applied, every other base fluent keeps its value (inertia), every numeric fluent then moves by its drift, and the derived fluents are recomputed. Applying a step's events together gives the same state as applying them one at a time in any order, the drift added once after all of them.
- **Episodes and histories.** An episode runs the world over a few participants for a few steps. Participants are drawn around a seed entity, weighted by thematic relatedness and taxonomic similarity. At each step a selection policy draws events among the legal ones; by default (`uniform_event`) it draws uniformly among all legal events, so an event type that is legal for many bindings happens more often, as in a world where some things simply happen more. An episode ends after its steps, or earlier when nothing is legal (quiescence). A **history** records the episode: its participants, its initial state (the numeric values among it), and each step's events with the changes they made, every numeric change with its cause (an event, or the drift). The corpus calls an episode a scene.
- **Places** (stage c1 of phase (c)) are a second kind of object, the world's grain of interaction: `PLACE.1.2.1`, the instances of a second taxonomy run with labels of its own (`PLACECATEGORY`, `PLACEPROPERTY`, `PLACEPART`, `PLACESCALARDIM`), which the world runs in memory on the configuration `places.taxonomy` names. Places are not entities: they have place features and place scalars, no fluents, and no location, and nothing that reads the entities' tables sees a place. A **place event type** (`PLACEEVENTTYPE.2`) has an entity as its agent and a place as its patient; its requirement is a conjunction of one or two constraints over the agent's features and the place's features (the same families as the two-place constraints, the comparison family comparing an entity scalar with a place scalar), drawn again when it holds for no binding or for every binding of the world, or, with the band `place_event_types.density: [low, high]` (the stage c3b follow-up, Jon's ruling WM.67), for a share of the bindings outside the band, up to 200 draws. Its capacities are `CAN.PLACEEVENTTYPE.2` (the entity is able to be the agent at some possible place) and `CANBE.PLACEEVENTTYPE.2` (the place is able to be the patient of some possible entity). A place event type has no precondition and no effects, and no episode includes one, until it is made a move or an act at a place (stage c3a, below), with location as a pair fluent toward places; stage c3b draws the moves and acts. `EVERYPLACE` is the comparison class of every place, as `ENTITY` is of every entity, and the runtime's comparisons accept places and means of categories of places on place scalars, never mixed with entity scalars.
- **Pair fluents** (stage c2a of phase (c)) are Boolean facts about two entities that change over time, `PAIRFL.1` to `PAIRFL.n`: near, above, follows. A pair fluent is stored as the set of ordered pairs for which it holds at a time point, and events add and delete its pairs. Each has a **profile**: its symmetry (`symmetric`: a pair holds exactly when its reverse does; `asymmetric`: never both; `general`: no constraint) and whether it is `functional` (at most one partner in each row, and for a symmetric functional pair fluent in each column too); every pair fluent is irreflexive, and a pair fluent between entities is never total (the total functional profile is location's, toward places, below). Since stage c2b the world draws `pair_fluents.count` pair fluents: each one's symmetry from `pair_fluents.symmetry`, whether it is functional at `pair_fluents.functional_rate`, and its **initial rate** from `pair_fluents.initial_rates`, at which the **initial pairs** are drawn once when the world is generated, respecting the profile (`initial_pairs.csv`); an override in the configuration, or an event file's entry, replaces the drawn profile of a pair fluent. The **pair literals** read them: `PAIRFL.2(agent, patient)` (the pair holds), `SOME.PAIRFL.2(agent)` (the agent's row holds a pair), `SOMEOF.PAIRFL.2(patient)` (the patient's column does), and `SAME.PAIRFL.3(agent, patient)` (the two share a partner, on a functional pair fluent), each positive or negated, in a precondition, in a condition, and (`SOME` and `SOMEOF` of the entity itself) in a derived fluent's rule. A **pair effect** adds or deletes the pair between the roles, `PAIRFL.2(agent, patient) := 1`; a symmetric add or delete writes both directions. The generator draws them at shares, as it draws numeric literals and effects: a share `event_types.preconditions.pair_share` (0.2) of the precondition literals is a pair literal, a share `event_types.effects.pair_share` (0.2) of the effects of two-place event types is a pair effect, a condition literal is a pair literal by the `pair` weight of `condition_kinds`, and the first `pair_fluents.derived_rules` derived fluents read a `SOME` or `SOMEOF` literal (the others may, at `pair_fluents.rule_weight`). Every drawn pair literal is achievable (a positive one needs an initial rate above 0 or some add, a negative one an initial rate below 1, a functional pair fluent, or some delete), `SAME` is drawn only on a functional pair fluent that is not symmetric, a one-place event type reads `SOME` and `SOMEOF` of its agent alone, and a pair condition never names a pair or row the precondition names, nor one whose value the precondition fixes. The generator compiles each profile into precondition literals of the origin `profile` (F4): an add on an asymmetric pair fluent gains `NOT PAIRFL.k(patient, agent)`, an add on a functional one `NOT SOME.PAIRFL.k(agent)` (and `NOT SOME.PAIRFL.k(patient)` too when it is symmetric), so that a legal event never breaks a profile and two events that could jointly break one interfere; the runtime still checks every profile after each step (a `ProfileViolationError`, which a correct definition never raises). A conditional add on an asymmetric or functional pair fluent is not allowed, because its compiled literals would not be a plain precondition. For non-interference an event reads the pairs, rows, and columns its literals read (through the cones of derived fluents) and writes the pairs its effects write, a row or a column counting as every pair in it. An event file may also give a **`spatial` block**, a detector and parameters for a pair fluent, which the 3D runtime will read; `definition.json` carries it with `spatial_id`, outside the rule-set identity. The corpus does not state pair fluents yet (stage c4), and refuses a world that has them.
- **Locations** (stage c3a of phase (c)). A **location fluent** is a pair fluent from entities to places with the fixed profile `general`, functional, and total: each entity is at exactly one place at every time point. The world has `pair_fluents.locations` of them (1 by default since stage c4a, Jon's ruling WM.63, and 0 with `places: null`; they need places), labeled after the pair fluents between entities, so `pair_fluents: {count: 1, locations: 1}` gives `PAIRFL.1` between entities and the location fluent `PAIRFL.2`, and the default world's location fluent is `PAIRFL.5`. A location fluent has no initial rate: each entity's **initial place** is drawn once, when the world is generated, from the stream `world:habitats`, with the weight `(1 + a(x, q)) ^ places.habitat_strength` for place `q`, where `a(x, q)` is the number of place event types whose requirement holds for the entity at the place, so that **habitats** emerge from what entities are able to do where (strength 0 gives a uniform draw); the places are columns of `entities.csv`, one per location fluent, named by its label. The literals on a location fluent are `PAIRFL.2(agent, patient)` and `SOMEOF.PAIRFL.2(patient)` ("someone is at the place") in a place event type, whose patient is a place, and `SAME.PAIRFL.2(agent, patient)` ("the two are at the same place") in an event type between entities; `SOME` of an entity on a location fluent is always true and is never allowed. Every place event type is a **move** or an **act at a place** (since stage c3b: an event file's `place_event_types` entry makes it one, and otherwise the generator draws its dynamics from `world:place_dynamics`, a move at `place_event_types.move_share`, an act otherwise, with its location fluent and further literals, effects, and conditions on the agent drawn as the entity event types draw theirs; its record carries `place_kind`, WM.65): a move has the effect `PAIRFL.2(agent, patient) := 1`, which the runtime applies as the total functional replacement, deleting the agent's old place in the same step, and the compiled literal `NOT PAIRFL.2(agent, patient)` of origin `move`, so that nothing moves to where it is) or an **act at a place** (the literal `PAIRFL.2(agent, patient)` of origin `act`, so that it happens at the agent's place); further literals read the agent (its Boolean and numeric fluents, `SOME` and `SOMEOF` of its pair fluents between entities) and, in a move, `SOMEOF` of the place, further effects write the agent's fluents, nothing writes a fact about a place, and nothing deletes a pair of a location fluent. Two-place event types between entities may require `SAME` on a location fluent (drawn at the pair share, and `pair_fluents.same_rules` of them must require it, so that location bears on interactions, WM.52). For non-interference a move writes the whole row of its agent, and `SOMEOF` of a place reads the place's column. An episode has **places**: the distinct places of its participants at `TIME.1` plus `scene.extra_places` (1) places drawn from the others, or every place with `scene.places: all`; a move goes only to a place of the episode; `scene.initial: redraw` redraws the participants' places with the habitat weights, and `scene.initial_location: seed` starts every participant at the seed entity's place. A history lists the episode's `places` and each participant's `initial_places`, and a move records the deletion of the old place and the add of the new one as two changes. `data/world/tiny_place_chain.yaml`, with `data/world/events/place_chain_example.yaml`, is the example (below). The drawn moves and acts, `SAME` on location fluents in drawn preconditions, the quota `same_rules`, and the location statistics come in stage c3b; the corpus refuses a world with location fluents, as it refuses any world with pair fluents, until stage c4.
- **Views** choose which columns of the base facts and the derived values a model sees. A view is an experiment setting, never part of the world.

The event types attach their preconditions and effects to the tree as well: an event-type feature can carry a precondition literal or an effect, and every event type with that feature inherits it, so a branch of the tree shares what it needs and what it does, as it shares its constraints.

### Where the world comes from

`define` runs the taxonomy generator first, in memory, and writes the run to `taxonomy/` inside the world's folder, byte-identical to the taxonomy run alone with the same configuration and seed. The taxonomy supplies the entities' static facts and the feature rules. The world package then draws, from streams of its own, the one-place requirements (`world:requirements`), the event-type tree and its constraints (`world:event_tree`, `world:constraints`, `world:pairs`), the fluents and their rules (`world:fluents`), the initial values (`world:initial`), the preconditions (`world:preconditions`), the effects (`world:effects`), the conditions (`world:conditions`), and, since stage b2, the numeric fluents' drift (`world:numeric`), their initial values (`world:numeric_initial`), and the numeric effects, precondition literals, and condition literals (`world:numeric_effects`, `world:numeric_preconditions`, `world:numeric_conditions`), and runs the statistics episodes (`world:stats`). Since stage c1 the place taxonomy runs with the seed of `world:places` (so it never repeats the entities' draws) and is written to `places/`, and the place event types' requirements, and the samples of their capacities' local test, come from `world:place_event_types`; both streams were created after every earlier one. Since stage c2a the initial pairs of the pair fluents come from `world:pair_initial`, after `world:pair_fluents`, from which stage c2b draws their profiles and rates; since stage c2b the pair literals of preconditions, the pair effects, and the pair condition literals come from `world:pair_preconditions`, `world:pair_effects`, and `world:pair_conditions` (a never-legal event type's redraw from `world:pair_preconditions:<label>`), all five after the place streams, so a world whose configuration draws no pair fluent is the world of stage c1, byte for byte (its `config.yaml` records the five seeds). Separate streams mean that changing the fluent, precondition, or effect settings never changes the taxonomy, the requirements, the capacities, or the relation statistics; that with `numeric_fluents.count: 0` a world is the world of stage b1, byte for byte, and with the numeric shares at 0 its Boolean dynamics are those of the world without numeric fluents; that with `places: null` a world is the world before places, byte for byte; and that with `pair_fluents: {count: 0}` a world is the world of stage c2a, byte for byte, while with the pair shares, the `pair` condition weight, `pair_fluents.rule_weight`, and `pair_fluents.derived_rules` at 0 its event types and derived rules are those of the world without pair fluents. `TAXONOMY.md`, "Where CAN features and verbs went", describes the requirements and the relation statistics in detail.

### Rules as matrices, and the rule-set identity

Every rule of a world (a determined feature, a derived fluent, a constraint, a requirement) is kept in two forms: the Boolean form, a truth table with an expression, which a reader can check, and the matrix form, two threshold layers, which the runtime computes (`docs/specs/WORLD_AND_LANGUAGE.md`, "Rules: Boolean form and matrices"). At the end of every run, the agreement test evaluates both forms on every entity and every ordered pair, and on every input setting of every rule with at most 12 inputs; a disagreement fails the run, because it would be a bug in the generator.

The **rule-set identity** is the SHA-256 hash of the canonical JSON of the definition's symbols, literals, rules, and event types. It changes exactly when a rule, a literal's number, or an event type changes. Every derived file and every history carries it, and a loader refuses a derived file or a history whose identity differs from the definition in use. `tests/fixtures/world/README.md` gives the exact rules of the canonical JSON, for whoever builds the Rust runtime.

## The commands

Every command runs from the root of the repository. With the repository's virtual environment active, `PYTHONPATH=python` is not needed.

### `define`

```
PYTHONPATH=python python -m semantic_world.world define data/world/tiny.yaml [--seed N] [--out DIR]
```

Generates a world and writes its folder (see "Reading the outputs"). The run embeds the taxonomy run and, since stage c1, the place taxonomy run, draws the pair fluents (their profiles and initial rates, since stage c2b, or those an event file gives) and their initial pairs, the fluents (Boolean and numeric), the event types, and the place event types, builds the definition, runs the agreement test (over every entity, every ordered pair of entities, every place, and every entity paired with every place) and the checks of the dynamics (no requirement reads a fluent, no effect writes a derived fluent, no contradiction, every precondition literal achievable, every numeric threshold inside its range, the rules of pair literals and effects under "The event file" and "Generated pair fluents", and, since stage c3a, the rules of moves and acts under "Place event types in the event file"), and runs 1,000 statistics episodes. With location fluents (stage c3a), it also draws each entity's initial place with the habitat weights, after every other draw, and (stage c3b) the dynamics of every place event type without an event-file entry, after every other draw of the event types, so that every world without location fluents draws as before. A literal's achievability counts every effect of the world, the place event types' included (Jon's ruling WM.66). An event type that is never legal in the statistics episodes has its own precondition literals drawn again, up to a few times; the command prints a note for each redraw, and a warning for each event type that is still never legal. The default world takes about 8 seconds (8.4 s on October 29, 2026, stage c4a, with its four pair fluents and its location fluent, which were `default_full.yaml`'s until then: 8.4 s on October 28, 2026; 6.8 s for the default world without them the same day, 6.9 s in stages c3b, c3a, and c2b, 6.8 s in stage c2a, 6.4 s in stage c1, 6.3 s in stage b3b, 6.1 s in stage b3a, 6.7 s in stage b2, 7.6 s in stage b1), of which the static side, the place taxonomy and the place event types included, is about a second; the tiny_place_chain world, with a location fluent, 2 seconds (1.9 s). Every stage records this time, measured with nothing else running, and flags a growth of more than half in its proposal file; there is no hard time limit, and no step is made cheaper by changing what it produces by default (Jon's ruling 3 on stage a8).

### `simulate`

```
PYTHONPATH=python python -m semantic_world.world simulate runs/world/tiny_seed1 --episodes 100 [--seed N] [--legal] [--out FILE] [--config data/corpus/default.yaml]
```

Runs episodes of a world run and writes them as histories, one JSON object per line, to `RUN/episodes.jsonl` or to `--out`. The command prints one line (from a run of October 10, 2026, on the tiny world; the line is not regenerated with the guide's other figures):

```
wrote runs/world/tiny_seed1/episodes.jsonl: 100 episodes, 762 events, 0 quiescent, policy uniform_event
```

The master seed is the run's seed unless `--seed` gives another; each episode draws from its own part of the stream `world:episodes`, named by its label, so episode 7 is the same whether 10 or 1,000 episodes are run. The scene settings (the number of participants, the number of steps, the events per step, the participant weights, the policy, the event-type weights, whether the initial state is kept or redrawn, and, since stage c3a, the episode's places: `extra_places`, `places`, and `initial_location`) are the corpus's defaults, or the `scene` block of a corpus configuration file given with `--config`. With `--legal`, each step also records the number of legal bindings of each event type among the participants, so legality and occurrence can be studied apart; it is off by default because of size.

### `view`

### `definition.json`

The language-neutral part of the definition, with no code in it. Its top-level keys:

- `version`: the format's version, 1;
- `rule_set_id`: the rule-set identity;
- `symbols`: one entry per feature, scalar, fluent, numeric fluent, pair fluent, event type, and event-type category: `label`, `kind` (`property`, `part`, `scalar`, `fluent`, `numeric_fluent`, `event_type`, `event_type_category`, with places `place_property`, `place_part`, `place_scalar`, `place_event_type`, and with pair fluents `pair_fluent`), `derived`, `fluent`, `arity`, for a base fluent its `initial_rate`, for a numeric fluent its `range`, its `initial` distribution, and its `drift`, and for a pair fluent (stage c2a, arity 2) its profile, `symmetry`, `functional`, and `total` (true for a location fluent, stage c3a, which is general and functional and comes after the pair fluents between entities), and its `initial_rate` (null for a location fluent);
- `literals`: everything the rules read, each with its `index`, its `key`, its `kind` (`feature`, `threshold`, `fluent`, `numeric_threshold`, `comparison`, `constraint`, and, since stage c2a, `pair_some` and `pair_someof`, the `SOME` and `SOMEOF` literals of a derived fluent's rule about its own entity, computed from the state's pairs before the matrices), its `role` (null for the entity itself, `agent`, `patient`, or `binding`), and the fields of its kind;
- `rules`: every rule's `output`, `scope` (`entity` or `binding`; with places also `place`, a determined place feature, and `place_binding`, a place event type's constraint or requirement over an entity and a place), `family`, `inputs` (literal indices), `truth_table`, and `expression`. A derived feature and a derived fluent are entity rules; a constraint and a requirement are binding rules;
- `layers`: the matrix form, written sparsely: for each layer its `terms` (the literals of one term of the rule's minimal DNF, whether each is complemented, and the threshold) and its `outputs`;
- `event_types`: one entry per event type and category, and per place event type (kind `place_event_type`, arity 2, its patient a place; since stage c3b every place event type of a world with location fluents is a move or an act, from an event file's entry (`explicit` true) or drawn, and its record holds its precondition and effects as an entity event type's does, plus `place_kind` (`move` or `act`, right after `kind`; part of the rule-set identity, and absent from a place event type without dynamics, Jon's ruling WM.65)): `label`, `kind`, `arity`, `roles`, `parent`, `level`, `features`, `explicit`, the `requirement` (its constraints, the rule that is the requirement, and the expression), the `precondition` (its literals, each a `role`, `fluent`, and `value`, or, for a numeric threshold literal, a `role`, `fluent`, `operator` (`>` or `<=`), and `threshold`, or, since stage c2a, a pair literal with a `kind` (`pair`, `pair_some`, `pair_someof`, `pair_same`), its `pair_fluent`, its roles (`first` and `second`, or `role`), its `value`, and, for a compiled literal, its `origin` (`profile`; since stage c3a `move` for a move's `NOT PAIRFL.k(agent, patient)` and `act` for an act's `PAIRFL.k(agent, patient)`); and the expression), and the `effects` (each a `role`, `fluent`, `value`, and expression, or, for a numeric effect, a `role`, `fluent`, `operator` (`+=` or `-=`), `amount`, and expression, or, for a pair effect, a `kind` (`pair`), `pair_fluent`, `first`, `second`, `value`, and expression; and, for a conditional effect, a `condition` with its literals, each a `role`, `kind` (`feature`, `fluent`, or `numeric`), `symbol`, and `value` or `operator` and `threshold`, or a pair literal as in a precondition, and its expression; an unconditional effect has no `condition` key);
- `spatial` and `spatial_id` (stage c2a), only when the event file gave a `spatial` block: for a pair fluent, a `detector` name and its `parameters`, and the SHA-256 hash of the block's canonical JSON. Neither is part of the rule-set identity; the Python runtime checks the block's form and nothing else.

Floating-point numbers are written with 17 significant digits, so both runtimes read the same values. With `places: null`, no place symbol, literal, rule, layer, or event type is written, so the definition and its identity are those of the world before places; without pair fluents, no pair symbol, literal, record, or `spatial` key is written, so the definition is that of stage c1. `tests/fixtures/world/README.md` describes every field, and how the layers are evaluated.

### `world_stats.yaml`

- `fluents`: the counts of base and derived Boolean fluents.
- `event_types`: the counts of one-place event types, two-place event types, and categories.
- `precondition_literals` and `effects`: the totals, by kind of event type, by role, and how many come from event-type features (numeric literals and effects counted among them); under `effects`, the `conditional` effects by kind of event type and the `condition_literals` by symbol kind (`feature`, `fluent`, or `numeric`, and `pair` when the world has a pair condition literal, stage c2a), by role, and from event-type features (stage b1).

- `enabling_graph`: the edges from an event type whose effect produces a value to an event type whose precondition requires it (a numeric effect that adds enables a literal `>`, one that subtracts a literal `<=`), and the longest chain.
- `absorbing_fluents`: the base Boolean fluents that some effect sets to one value and no effect sets back.
- `numeric_fluents` (stage b2): the count, how many drift, each fluent's `range`, `initial` distribution, and `drift`; the numeric `effects` by operator (`add`, `subtract`), by kind of event type, by role, and from event-type features; the numeric `precondition_literals` by side (`above` for `>`, `at_or_below` for `<=`), by kind of event type, by role, and from features; the numeric `condition_literals` by side and role; and `rules_reading_a_threshold`, the derived Boolean fluents whose rule reads a numeric threshold.
- `relations`: the event-type features, categories, event types, and constraints by family, and the density report.
- `places` (stage c1): the places and their categories, the place features by kind (`place_property` and `place_part`, free and determined, and `place_scalar`), the place event types, their constraints by family, each requirement's `density` over the world's bindings (an entity and a place) with its `tries`, the share of approximate capacities, and warnings, and, with a density band (WM.67), the band (`density_band`) and the place event types still outside it after the draws (`outside_density`, `outside_density_labels`); null with `places: null`. In a world with location fluents (stage c3b) also `place_event_types_by_kind` (`moves`, `acts`, `without_dynamics`, `explicit`), `dynamics` (the counts of the drawn place dynamics: the effects, literals, and conditions drawn and drawn again, the numeric and pair replacements), and `habitats`, per location fluent: for each place category the share of each entity superordinate's entities that start there (`by_place_category`), the largest deviation of such a share from the uniform share (`largest_deviation`), the entropy in bits of each entity category's initial places over the places (`entropy_by_category`), its mean by level of the entity tree (`mean_entropy_by_level`), the entropy of the uniform draw (`max_entropy`), and, under Jon's ruling WM.69, the expected effect sizes at the leaf level (`expected_by_leaf`), computed from the habitat weights rather than from the draw: `level`, the leaf level of the entity tree; `favorite_ratio`, the median and the largest, over the entity leaf categories, of the ratio of a category's expected share at its favorite place leaf category to that category's uniform share (its places over the places), with the `category` and the `place_category` of the largest; and `entropy`, the `mean` expected entropy, in bits, of the entity leaf categories' places over the place leaf categories, against `uniform`, the entropy of the uniform draw grouped by place leaf category (the mean at strength 0).
- `pair_fluents` (stage c2b, only in a world with pair fluents): the pair fluents by symmetry (`by_symmetry`) and how many are functional, each fluent's profile, `initial_rate` (null for a location fluent, whose `initial_pairs` are the entities' initial places, stage c3a), and `initial_pairs`, the total `initial_pairs`; the pair `precondition_literals` by kind (`pair`, `pair_some`, `pair_someof`, `pair_same`), role, polarity, and kind of event type, and from event-type features; the `compiled_literals` by origin; the pair `effects` by value (`add`, `delete`), role, kind of event type, and pair fluent, and from features; the pair `condition_literals` by kind and role; `rules_reading_a_pair_literal`, the derived fluents whose rule reads `SOME` or `SOMEOF`; `fix_ups`, the draws against each share, the replacements, the candidates drawn again, the adds whose compiled literals contradicted the precondition, the pair conditions drawn and the conditions rejected for a pair literal (named by the precondition, fixed by it, or breaking another rule), the adds that keep no condition, and, with location fluents (stage c3b), the literals replaced by `SAME` on a location fluent at the share (`same_location_replacements`), the event types the quota gave such a literal (`same_rules_added`), and the quota's shortfall (`same_rules_short`); and `pair_changes_per_event`. - `episodes`: the 1,000 statistics episodes of the default policy with the corpus's default scene settings, on the stream `world:stats`: for each event type the share of steps at which it had a legal binding (`legal_share`) and at which it occurred (`occurrence_share`), the mean number of Boolean changes per event, the mean number of numeric changes per event (`numeric_changes_per_event`) and of drift changes per step (`drift_changes_per_step`), the share of quiescent episodes, the two-place share (`two_place_share`: the share of two-place events among all events), the mean number of pair changes per event (`pair_changes_per_event`, in a world with pair fluents), with location fluents (stage c3b) the share of events that are moves (`move_share`), the share that are acts (`act_share`), and the two-place share counting the place event types apart (`two_place_share_entities`, the share of events of two-place event types between entities; the three sum to `two_place_share`), the precondition redraws, and the event types that were never legal.

### Histories

A history is one JSON object per episode: its `label`, its `seed` entity, its `participants`, the `policy`, the `rule_set_id`, the `initial` base fluents of each participant, the `steps` (each with its `events`, and each event with its `label`, `type`, `agent`, `patient`, and `changes`), the `final` time point, and `quiescent`. From the tiny world:

```json
{"label": "SCENE.1", "seed": "INSTANCE.1.1.2", "participants": ["INSTANCE.1.1.2", "INSTANCE.1.1.3", "INSTANCE.1.2.1"],
 "policy": "uniform_event", "rule_set_id": "bd02c67e7286...",
 "initial": {"INSTANCE.1.1.2": ["BOOLFL.3"], "INSTANCE.1.1.3": ["BOOLFL.1", "BOOLFL.3"], "INSTANCE.1.2.1": ["BOOLFL.3"]},
 "steps": [{"step": 1, "events": [
   {"label": "SCENE.1.EVENTINSTANCE.1", "type": "EVENTTYPE2.2.1", "agent": "INSTANCE.1.1.3", "patient": "INSTANCE.1.2.1",
    "changes": [{"entity": "INSTANCE.1.1.3", "fluent": "BOOLFL.2", "to": true}]},
   {"label": "SCENE.1.EVENTINSTANCE.2", "type": "EVENTTYPE1.2", "agent": "INSTANCE.1.2.1",
    "changes": [{"entity": "INSTANCE.1.2.1", "fluent": "BOOLFL.1", "to": true}]}]}, ...],
 "final": "TIME.5", "quiescent": false}
```

`changes` lists only the base fluents whose value changed: an effect that sets a fluent to the value it already has records nothing, an effect whose condition failed records nothing, and a derived fluent's change is never recorded, because it is recomputed. In a world with numeric fluents (stage b2), a history also holds `initial_numeric` (each participant's numeric values at `TIME.1`), an event's `changes` hold the numeric changes its effects made, each `{"entity", "fluent", "from", "to", "cause"}` with the event's own label as its cause, judged after the effect and before the drift, and a step holds the drift's changes to the participants under `drift`, each with `"cause": "drift"`; so every numeric change is recorded with its cause, and a reader can rebuild the values at every time point from the history alone. A world without numeric fluents writes none of these keys. In a world with pair fluents (stage c2a), a history also holds `initial_pairs` after `initial_numeric`, every ordered pair that holds among its participants at `TIME.1` as `[pair fluent, first, second]` triples (an episode keeps the pairs among its participants and no other, WM.38), and an event's `changes` hold its pair changes, each `{"pair": "PAIRFL.1", "first": ..., "second": ..., "to": true}`, a symmetric pair once in the direction the effect names; `replay` writes both directions and reproduces every pair at every time point. A world without pair fluents writes neither key. In a world with location fluents (stage c3a), a history also holds `places` after `participants` (the episode's places) and `initial_places` after `initial_numeric` (each participant's place on each location fluent at `TIME.1`), a move's patient is a place label, and a move's `changes` hold the deletion of the old place and the add of the new one, each `{"pair": "PAIRFL.2", "first": ..., "second": "PLACE.2.1", "to": ...}`; `replay` checks that every entity is at exactly one place at every time point. A world without location fluents writes neither key. The corpus's `scenes.jsonl` holds the same schema, and the 3D engine will write it too. `tests/fixtures/world/README.md`, "Histories", gives every field, and "The order within a step" the arithmetic a runtime must reproduce bit for bit.

Every precondition literal must be achievable (a Boolean literal's value is some entity's initial value, or some effect produces it; a numeric literal `> t` holds of some entity's initial value, or its fluent drifts upward, or some effect adds to it, and `<= t` the other way round) and consistent (a precondition never holds two literals on one fluent of one role); the generator redraws or drops a literal that is not, and counts it under `fix_ups`. Every condition must be satisfiable with its event type's requirement and precondition: some able binding satisfies its static literals (for every event type that inherits the effect), each fluent literal is achievable, names no fluent of a role that the precondition names, and never names the Boolean fluent the effect sets (a numeric condition on the effect's own numeric fluent, "when low, add", is a real condition and allowed); the conditions are drawn from a stream of their own (`world:conditions`), so changing their settings changes nothing else, and a condition that breaks a rule is drawn again (`fix_ups.conditions_redrawn`).

**The event file.** An event file defines fluents and event types by hand, over the world's abstract labels, as a rule file defines rules: a base fluent's initial rate, a numeric fluent's initial distribution and drift (`NUMFL.1: {initial: {kind: fixed, value: 0.5}, drift: 0.1}`), and an event type's requirement, precondition, and effects. An entry replaces the sampled dynamics of the event type it names; event types without an entry are sampled. A precondition may hold numeric threshold literals (`agent.NUMFL.1 > 0.75`, `agent.NUMFL.1 <= 0.75`), an effect may be numeric (`agent.NUMFL.1 -= 0.2`), and an effect may carry a condition, written `when agent.PROPERTY.1 AND NOT patient.BOOLFL.2 then patient.BOOLFL.2 := 1`. `data/world/events/chain_example.yaml` builds a chain of two event types, catch and eat, whose second needs the first's effect:

```yaml
fluents:
  BOOLFL.1: {initial_rate: 1.0}        # say, awake
  BOOLFL.2: {initial_rate: 0.0}        # say, caught
event_types:
  EVENTTYPE2.1.1:
    requirement: "agent.SCALARDIM.1 - patient.SCALARDIM.1 > 0.0"
    precondition: "agent.BOOLFL.1 AND NOT patient.BOOLFL.2"
    effects: ["patient.BOOLFL.2 := 1"]
  EVENTTYPE2.1.2:
    requirement: "agent.SCALARDIM.1 - patient.SCALARDIM.1 > 0.0"
    precondition: "agent.BOOLFL.1 AND patient.BOOLFL.2"
    effects: ["patient.BOOLFL.1 := 0"]
```

An entry that breaks a rule of the world (an effect on a derived fluent, a requirement that reads a fluent, a contradiction, an unachievable literal, a numeric threshold outside its fluent's range, a condition that no able binding satisfies or that reads the effect's own Boolean fluent or a fluent the precondition fixes) is an error that names the file and the entry. `data/world/tiny_chain.yaml` uses the file with the tiny world.

**Pair fluents in the event file** (stage c2a). A `pair_fluents` block defines pair fluents between entities, `PAIRFL.1` and on without a gap, each with its profile and its initial rate; the preconditions and conditions may then hold pair literals, the effects may add or delete pairs, and a `spatial` block may give a detector for a pair fluent. `data/world/events/pair_example.yaml` defines four pair fluents (one of each symmetry, two of them functional) and five event types over them, and `data/world/tiny_pairs.yaml` uses it with the tiny world:

```yaml
pair_fluents:
  PAIRFL.1: {symmetry: symmetric, functional: false, initial_rate: 0.2}    # say, near
  PAIRFL.3: {symmetry: general, functional: true, initial_rate: 0.2}       # say, follows
event_types:
  EVENTTYPE2.1.1:                                                          # approach
    precondition: "NOT PAIRFL.1(agent, patient)"
    effects: ["PAIRFL.1(agent, patient) := 1"]
  EVENTTYPE2.1.2:                                                          # follow
    precondition: "PAIRFL.1(agent, patient)"
    effects:
      - "PAIRFL.3(agent, patient) := 1"
      - "when SOME.PAIRFL.2(patient) then patient.BOOLFL.1 := 0"
spatial:
  PAIRFL.1: {detector: within, parameters: {distance: 1.0}}
```

The compiled literals are added to explicit entries too: `EVENTTYPE2.1.2` gains `NOT SOME.PAIRFL.3(agent)`, because `PAIRFL.3` is functional. Since stage c2b the file's entries replace the drawn profiles of the pair fluents they name, which must be among `PAIRFL.1` to `PAIRFL.<count>` of the configuration's `pair_fluents.count` (`tiny_pairs.yaml` sets 4); a pair fluent the file does not name is drawn. An entry that breaks a rule of "Pair fluents" is an error that names the file and the entry: a `SAME` literal on a pair fluent that is not functional (or on a symmetric functional one, which no two entities can share), a pair literal that is not achievable (a positive literal needs a positive initial rate or some add; a negative one an initial rate below 1, a functional pair fluent, or some delete), two effects on the same pair (both directions of a symmetric pair are one pair), an add whose precondition already requires the pair or a delete whose precondition already requires its absence, a conditional add on an asymmetric or functional pair fluent, a pair condition that names a pair or a row the precondition (its compiled literals included) names or the pair the effect itself writes, and compiled literals that contradict the entry's own precondition. A one-place event type reads `SOME` and `SOMEOF` of its agent only. A location fluent is never defined in an event file (`total: true` is an error): the configuration's `pair_fluents.locations` makes them.

**Place event types in the event file** (stage c3a). A `place_event_types` block makes place event types performable: `PLACEEVENTTYPE.<n>: {kind: move | act, requirement, precondition, effects, location}`. The label must be a place event type of the world; `requirement`, when given, replaces the drawn requirement (over `agent.` literals of the entity's features and scalars and `patient.` literals of the place's features and scalars, or a comparison of an entity scalar with a place scalar); `location` names the location fluent the entry uses, and may be left out when the world has one. A move gets the effect `PAIRFL.k(agent, patient) := 1` and the compiled literal `NOT PAIRFL.k(agent, patient)` (origin `move`); an act gets the literal `PAIRFL.k(agent, patient)` (origin `act`); a literal or an effect the entry gives by what it names is kept as given and not added twice. Further precondition literals read the agent's fluents, `SOME` and `SOMEOF` of the agent's pair fluents between entities, and `SOMEOF.PAIRFL.k(patient)` of the place; further effects write the agent's Boolean and numeric fluents, with conditions of the same kinds; a condition whose value the precondition fixes (an act's location literal fixes `SOMEOF.PAIRFL.k(patient)` true, so an act's condition never reads it) is refused, for place and entity entries alike (the stage c3b follow-up, Jon's ruling WM.68). `data/world/events/place_chain_example.yaml` builds the chain of go, approach, and eat over the tiny world (`data/world/tiny_place_chain.yaml`: one pair fluent between entities, one location fluent, two place event types, and no generated pair draws):

```yaml
pair_fluents:
  PAIRFL.1: {symmetry: symmetric, functional: false, initial_rate: 0.0}   # near
event_types:
  EVENTTYPE2.1.1:                                                          # approach
    precondition: "SAME.PAIRFL.2(agent, patient) AND NOT PAIRFL.1(agent, patient)"
    effects: ["PAIRFL.1(agent, patient) := 1"]
  EVENTTYPE2.1.2:                                                          # eat
    precondition: "agent.BOOLFL.1 AND PAIRFL.1(agent, patient)"
    effects: ["patient.BOOLFL.1 := 0"]
place_event_types:
  PLACEEVENTTYPE.1: {kind: move, requirement: "TRUE"}                      # go to
  PLACEEVENTTYPE.2:                                                        # rest
    kind: act
    requirement: "patient.PLACEPROPERTY.1"
    precondition: "agent.BOOLFL.1"
    effects: ["when SOMEOF.PAIRFL.2(patient) then agent.BOOLFL.1 := 0"]
```

An entry that breaks a rule is an error that names the file and the entry: an act whose precondition denies its location literal, a move whose precondition requires the agent at the place, a delete on a location fluent, an add on a location fluent in an act or in an event type between entities, `SOME` of an entity on a location fluent, `SOMEOF` of the agent on one, `SAME` on one in a place event type (or `PAIRFL.k(agent, patient)` on one in an event type between entities), a pair fluent between entities read as a pair or written in a place event type, a literal, an effect, or a condition on the place (a place has no fluent), a kind other than `move` and `act`, a location fluent the world does not have (or none named when it has several), an unknown place event type, and the rules of "Pair fluents in the event file" for the other literals. A world without location fluents refuses every `place_event_types` entry.

**Generated pair fluents** (stage c2b). With `pair_fluents.count` above 0 the world draws its pair fluents and what reads and writes them, from streams of their own, so that with the count at 0 nothing is drawn and the world is the world of stage c2a, and with the pair shares, the `pair` condition weight, `rule_weight`, and `derived_rules` at 0 the event types and the derived rules are those of the world without pair fluents (the pair fluents exist with their initial pairs, and nothing reads or writes them). Each pair fluent's profile and initial rate are drawn in label order from `world:pair_fluents`, three draws each; an override of `pair_fluents.fluents.PAIRFL.<n>`, or an event file's entry, replaces the drawn values after the draws, so it shifts no other pair fluent's draws. A precondition literal is drawn as before and then replaced by a pair literal at `event_types.preconditions.pair_share`, from `world:pair_preconditions`: its kind from `pair_fluents.literal_kinds` among the kinds the event type can take (`SAME` needs a functional pair fluent that is not symmetric, on which it could never hold; a one-place event type takes `some` alone), its pair fluent uniformly among those the kind allows, its direction (which role comes first), or its form (`SOME` or `SOMEOF`) and role, and its polarity, each uniformly; a candidate that is not achievable, that fills a slot the precondition already fills (a pair, a row, or a column it names), or that names or fixes what a pair condition of the event type reads is drawn again, and after the generator's limit the drawn literal is kept. An effect of a two-place event type (an own effect, or an event-type feature's) is drawn as before and then replaced by a pair effect at `event_types.effects.pair_share`, from `world:pair_effects`: the pair fluent, the direction, and the value (an add or a delete), each uniformly. The fix-ups of the dynamics then apply to pairs as to fluents: two effects on one pair with different values (both directions of a symmetric pair are one pair) are a contradiction, an add whose precondition requires the pair or a delete whose precondition requires its absence changes nothing, and an add whose compiled literals would contradict the precondition could never happen; an own effect is drawn again and an inherited one dropped, and the compiled literals of every add are appended once no contradiction is left. A condition literal of the kind `pair` is drawn the same way from `world:pair_conditions`; a condition is drawn again when its pair literal is not achievable, is the pair the effect itself writes, names a pair or row the precondition (its compiled literals included) names, or has a value the precondition fixes (a positive `PAIRFL.k(agent, patient)` fixes `SOME.PAIRFL.k(agent)` and `SOMEOF.PAIRFL.k(patient)`, and for a symmetric pair fluent the reverse pair and the other row and column; `NOT SOME.PAIRFL.k(agent)` fixes `PAIRFL.k(agent, patient)` and `SAME.PAIRFL.k(agent, patient)` false; and so on, as `docs/specs/WORLD_PHASE_C.md`, "Conditions (F5)", lists). An add on an asymmetric or functional pair fluent keeps no condition, because its compiled literals would not be a plain precondition. Two more rules follow Jon's rulings of October 21, 2026, on the stage's open questions: a delete on a pair fluent that can never hold (an initial rate of 0 and no add on it anywhere in the world) can never change anything, so it is drawn again as an empty effect is, until the world is stable (the pair fluent itself stays as it is, a frequency of the world); and a drawn precondition literal implied by, contradicted by, or implying another literal of the same precondition (`PAIRFL.k(agent, patient)` implies `SOME.PAIRFL.k(agent)` and `SOMEOF.PAIRFL.k(patient)`, and both rows and columns for a symmetric pair fluent; `NOT SOME.PAIRFL.k(agent)` implies `NOT PAIRFL.k(agent, patient)`; and so on) is drawn again, a compiled literal never. One event type also never adds both directions of an asymmetric pair fluent. An event file keeps the exact rules of stage c2a for its own entries, except that it may not add both directions of an asymmetric pair fluent either. The first `pair_fluents.derived_rules` derived fluents draw a rule that reads `SOME.PAIRFL.k` or `SOMEOF.PAIRFL.k` of the entity itself beside a fluent of the layer below, and the other derived fluents may, with `SOME` and `SOMEOF` in their input pool at `pair_fluents.rule_weight`. A never-legal event type's redraw draws its pair replacements from `world:pair_preconditions:<label>`. `world_stats.yaml` reports it all under `pair_fluents`.

## The two-place share

Two-place events are the events with a patient. Their share among all events is a frequency of the world, and follows from the world's constraints ("A principle for defaults" in the specification): a scene of a few participants has many able agents and few able pairs, so one-place events dominate unless the requirements make room. Stage a7a retuned five settings of `data/world/default.yaml` so that the share is about a third on the default world (Jon's ruling): the event-type tree has 5 superordinates with 4 event types each (as many two-place event types as one-place ones); a two-place event type has no constraint of its own beside its features' (`own_constraint: false`), so a requirement is a conjunction of about three constraints rather than four; the key-lock family, which holds for the fewest pairs, has half the weight of the others; the constraints weigh OR four times as much as AND and XOR, so each holds for more pairs; and the one-place requirements weigh AND three times as much as OR and XOR, so they are stricter. Without own constraints, two event types that share their true event-type features have the same requirement, and one whose true features are a subset of another's has the weaker one; the tree keeps every pair of event types apart on some feature.

The numeric fluents of stage b2 move them more, by up to 0.19 on seed 2, where the two-place event types drew thirteen `<=` literals, no fluent drifts, and the numeric effects mostly add, so that the literals go false and two event types of one branch are never legal; on seeds 1 and 3 the share rises, because a numeric literal that replaces a Boolean one is more often true (a value uniform over the range is above a quarter point three times in four). The mean over the five seeds falls from 0.368 to 0.339; the static side is unchanged.

What each lever does, against the baseline's share of 0.41 over seeds 1 to 3:

- **The number of event types of each kind** moves the share as a count: forty one-place event types lower it to 0.32 and ten raise it to 0.45; seven two-place event types lower it to 0.14 and forty raise it to 0.36 against the baseline's twenty at 0.41, because every event type's own feature draw changes the densities too.
- **The number of constraints per two-place event type** is the strongest lever: one true event-type feature per event type raises the density to 0.38 and the share to 0.63, six true features lower them to 0.03 and 0.05, and the own constraint of the code's default gives 0.08 and 0.27. Each constraint removes roughly half the pairs, so the density falls geometrically with their number.
- **The constraint-family weights**: the key-lock family holds for the fewest pairs, so equal weights give a density of 0.08 and a share of 0.30, while no key-lock, or comparisons alone, give 0.18 and 0.43.
- **The complexity of the constraints** matters less: the taxonomy's equal operator mix gives 0.11 and 0.35 against the OR-weighted mix's 0.15 and 0.41, and arities of 1 and 2 alone give 0.13 and 0.32. A constraint with more OR holds for more pairs.
- **The complexity of the one-place requirements** moves the one-place capacity rate (0.62 with the equal mix, 0.50 with AND weighed 3, 0.34 with AND alone, 0.33 with arities of 2 to 4) and the share by a few hundredths to a tenth (0.37, 0.41, 0.49, 0.51): fewer able agents leave more room for the two-place events.
- **The precondition settings**: with no preconditions at all the share is 0.50, with no feature literals 0.46, with more own literals 0.36, and with a feature rate of 0.6 only 0.15. Two-place event types carry the literals of their features beside their own, so preconditions bear on them more, and feature literals most of all: a literal on a feature blocks every event type of the branch.
- **The scene size** moves the share as the number of ordered pairs against the number of participants: small scenes of 2 to 4 participants give 0.27, large ones of 7 to 11 give 0.59. **`events_per_step`** barely moves it (0.43 at 0.5 and 0.38 at 4): the policy draws one event at a time among what is legal, and more draws mostly add one-place events once the few able pairs are taken.
- **`event_type_weights`** moves the share directly under `uniform_event`: two-place event types weighed 3 give 0.64, one-place event types weighed 3 give 0.21.

## The conformance fixtures

The Rust runtime, when it is built, must give the same results as the Python runtime. The conformance fixtures in `tests/fixtures/world/` are its tests, written now. Each fixture is one JSON file with a complete definition inline, the entities' static facts, the initial state, and a list of steps; each step gives its events and what must come out: the legal bindings of every event type before the step, and the state and the derived fluents after it. A fixture can end in an error that `apply` must raise, an illegal event or interfering events.

Two kinds are committed: forty-four hand-written fixtures over a hand world of three entities (and, since stage c3a, two places), with every expected value worked out by hand (a fluent with no event; an effect that sets, clears, or leaves a fluent; a derived fluent that changes; a precondition that blocks; two events that do not interfere; the kinds of interference; since stage b1, a static condition that holds and one that fails, a condition on a derived fluent that holds and one that fails, and interference through a condition; since stage b2, the comparisons, with ties, `ENTITY`, and a category mean, a numeric effect, the drift, clamping at both ends of the range, an effect and the drift in one step, a numeric precondition at its threshold, a numeric condition, and interference through a numeric fluent; and, since stage c2a, over three pair fluents, a symmetric add and a symmetric delete that write both directions, an asymmetric add and a functional add blocked by their compiled literals, a derived fluent over `SOME` that changes with a pair, interference through the same pair, through a functional row, and through both directions of an asymmetric pair, and a pair condition that holds and one that fails; and, since stage c3a, over a location fluent and three place event types, a move that replaces the old place, a move to the agent's own place blocked by its compiled literal, an act legal at the agent's place and not elsewhere, `SAME` that holds and the event legal, `SAME` that fails after a move, `SOMEOF` of a place in a precondition, and interference between a move and an event that reads the mover's place through `SAME`), and six generated from the tiny world, numeric fluents and places included, with expected values from a brute-force evaluator that reads the truth tables and never the matrices (the pair sets directly, never the matrices, since stage c2a). A fixture of a world with pair fluents carries `initial_pairs` beside `initial` and `pairs` after each step, and one of a world with location fluents `initial_places` too (stage c3a), its `pairs` listing the location pairs after the others. `check-fixtures` runs every fixture through the runtime and then through the evaluator, so the two implementations check each other. `tests/fixtures/world/README.md` is written for whoever builds the Rust runtime: the fixture format, the definition record, the canonical JSON behind the rule-set identity, how literals and layers are evaluated, the semantics of each operation, the order within a step and the float format, and the comparisons.

## Using the package from Python

```python
from semantic_world.world.config import load_config
from semantic_world.world.generate import define

config = load_config("data/world/tiny.yaml", seed=7)
result = define(config)
result.write("runs/world/tiny_seed7")
```

`result` holds everything the run produced: `result.taxonomy` (the embedded taxonomy run), `result.statics` (the static side: the one-place requirements, the event-type tree, the relations, the capacities, and the relation statistics), `result.fluents`, `result.numeric` (the numeric fluents, with their ranges, distributions, drifts, and initial values), `result.event_types` (every event type with its requirement, precondition, and effects), `result.places` (the place taxonomy run, the place event types with their requirements over every binding, and their capacities; None with `places: null`), `result.pair_fluents` (the pair fluents and their initial pairs, stage c2a; empty without an event file that defines them), `result.definition` (the definition, with `result.rule_set_id`), `result.stats` (the contents of `world_stats.yaml`), and `result.warnings`. `config_from_mapping` in the same module builds a configuration from a dictionary, for sweeping a setting in code.

The runtime works on a loaded definition:

```python
from semantic_world.world.definition import load_definition
from semantic_world.world.runtime import apply, derive, initial_state, legal_bindings

definition = load_definition("runs/world/tiny_seed1")
state = initial_state(definition)
legal = legal_bindings(definition, state, "EVENTTYPE2.1.2")   # every legal binding, as pairs of entity indices
```

`derive(definition, state, entities)` gives the derived facts, `able(definition, event_type, bindings)` and `legal(definition, state, event_type, bindings)` judge bindings (for a place event type, bindings of an entity index and a place index, since stage c1), `legal_bindings` lists every legal binding among given entities in a fixed order (and among given places, `legal_bindings(definition, state, event_type, entities, places)`, for a place event type), and `apply(definition, state, events)` gives the state after one step, or raises an `IllegalEventError` or an `InterferenceError` that names the event and the reason (an event of a place event type is refused in stage c1); `apply_step` returns the numeric values after the effects and before the drift beside the state; a `ProfileViolationError` after a step marks a broken definition (stage c2a). A `State` holds `values` (the Boolean fluents), `numeric` (the numeric fluents, float64), and `pairs` (one Boolean matrix per pair fluent, stage c2a; `State.from_true` takes the pairs as label triples, and `pairs_record` gives them back). The comparisons are `greater(definition, dimension, x, y, state)`, `above(definition, dimension, x, standard, z, state)` and `below`, and `increase(definition, fluent, x, before, after)` and `decrease`, over entities by index or `Mean(category)`, with `ENTITY` and `RANGE` as the symbols; `comparison_classes(definition)` gives every class's count, mean, and standard deviation. The runtime draws no random number and chooses no event. Episodes are run by `semantic_world.world.episodes.simulate(folder, episodes, seed, settings)`, or by an `EpisodeGenerator` over a definition in memory; `semantic_world.world.history.replay(definition, history)` checks a history against the runtime, every recorded numeric value to the bit, and returns its states.

## Recipes

- **Several worlds with the same settings.** Run the same configuration with `--seed 1`, `--seed 2`, and so on. The two-place share and the densities vary with the seed, as the table above shows.
- **A world without conditions.** `event_types: {effects: {conditional_share: 0}}` gives the unconditional world, with the same definition and identity as before stage b1 (apart from the numeric fluents of stage b2); `conditional_share: 1` makes every effect conditional.
- **A world without numeric fluents.** `numeric_fluents: {count: 0}` gives the world of stage b1, byte for byte. With numeric fluents kept but `event_types: {effects: {numeric_share: 0, condition_kinds: {feature: 1, fluent: 1}}, preconditions: {numeric_share: 0}}` and `numeric_fluents: {rule_weight: 0}`, the numeric fluents exist and drift but nothing reads or writes them, and every Boolean draw is as without them.
- **A world of needs.** `numeric_fluents: {count: 1, fluents: {NUMFL.1: {initial: {kind: beta, mean: 0.3, concentration: 4}, drift: 0.05}}}` with `event_types: {effects: {numeric_share: 0.5}, preconditions: {numeric_share: 0.5}}`: one fluent that rises at every step, which half the effects add to or subtract from and half the literals read.
- **A world without change.** `fluents: {count: 0}` and `numeric_fluents: {count: 0}`. Every able binding is legal at every time point, histories record no change, and `scene.policy: uniform_event_type` in the corpus then gives the scenes of the corpus's old scene generator.
- **A world without places.** `places: null` (and no `place_event_types` block): the world before stage c1, byte for byte, with no `places/`, `places.csv`, or `place_capacities.csv`. A study that wants other kinds of place names its own taxonomy configuration with `labels.kind: place` under `places.taxonomy`; `place_event_types.constraint_families: {comparison: 1}` makes every place requirement a comparison of an entity scalar with a place scalar.
- **A known chain of events.** Write an event file (above), and name it under `event_types.event_file`. `simulate` on the world shows the chain's events in the order the preconditions force.
- **A world with pair fluents.** Every configuration has them by default since stage c4a (`tiny.yaml` 2, `default.yaml` 4, generated as stage c2b draws them); `data/world/tiny_pairs.yaml` and an event file with a `pair_fluents` block (above) give pair fluents by hand. `simulate` records every pair change, and `initial_pairs.csv` the pairs at `TIME.1`. Since stage c4a the corpus runs on such a world, saying nothing about the pairs until stage c4b.
- **A world without pair fluents.** `pair_fluents: {count: 0, locations: 0}`: nothing is drawn from the pair streams, no place event type has dynamics, and the world is the world of stage c2a with the density band's place requirements (the snapshot's baseline `pair_fluents_off`); with `place_event_types: {density: null}` and `places: {habitat_strength: 1}` too, it is the world of stage c3b before stage c4a, with its dead Boolean effects drawn again (WM.70).
- **A world with locations.** Every configuration with places has one location fluent by default since stage c4a (stage c3b: every place event type a drawn move or act); `pair_fluents: {locations: 2}` gives a second, `pair_fluents: {locations: 0}` none, `place_event_types: {move_share: 1}` makes every drawn place event type a move (0: an act), `pair_fluents: {same_rules: 0}` turns the quota of `SAME` literals off, and `places: {habitat_strength: 0}` draws the initial places uniformly. `data/world/tiny_place_chain.yaml` (stage c3a) gives the place chain example's moves and acts from an event file instead (an entry's place event type is never drawn; the others are). `scene: {places: all, initial_location: seed}` in the corpus configuration given to `simulate --config` puts every place in every episode and every participant at the seed's place.
- **A world with pair fluents that nothing reads or writes.** `pair_fluents: {count: 4, rule_weight: 0, derived_rules: 0, same_rules: 0}` with `event_types: {preconditions: {pair_share: 0}, effects: {pair_share: 0, condition_kinds: {feature: 0.4, fluent: 0.4, numeric: 0.2, pair: 0}}}`: the pair fluents exist with their initial pairs, and the event types and derived rules are those of the world without them.
- **Pair fluents of a chosen profile.** `pair_fluents: {count: 2, fluents: {PAIRFL.1: {symmetry: asymmetric, functional: true, initial_rate: 0.05}}}` replaces the drawn profile of `PAIRFL.1` and leaves `PAIRFL.2`'s draws as they are; `initial_rates: [0.05, 0.2]` keeps every pair fluent alive from `TIME.1`.
- **More two-place events.** Lower `event_types.binary.features.expected_true`, or weigh the two-place event types in `scene.event_type_weights` of the corpus configuration; see "The two-place share" for every lever.
- **A model's input.** `view --preset classic` for the columns of the old `instances.csv`; `view --preset base --include ISA` for the base vector with the categories. Join `derived/capacities.csv` on `label` for the two-place capacities.
- **Legality apart from occurrence.** `simulate --legal` records, at every step, how many bindings of each event type were legal, beside the events that happened.

## Troubleshooting

- **"the preconditions of ... were drawn again".** A note, not an error: the event type was never legal in the statistics episodes, so its own precondition literals were redrawn. A warning names an event type that is still never legal after the redraws; it still exists, and the corpus never reports an event of it.
- **"never able".** An event type whose requirement holds for no entity or no pair gets no events and no word. The world keeps it; another seed, or looser `event_types.unary.rules`, gives another requirement.
- **A derived file is refused.** The file's rule-set identity differs from the definition's. The run folder holds files of two runs; regenerate it.
- **The agreement test fails.** The error names the rule and the first disagreement. The two forms of one rule set must agree, so this is a bug in the generator, not in the configuration. Keep the configuration and seed and report it.
- **An event file entry is refused.** The error names the file and the entry: an effect on a derived fluent, a requirement that reads a fluent, a contradiction, a literal that nothing can make true, a numeric threshold outside its range, a condition that breaks a rule (no able binding satisfies it, or it reads the effect's own Boolean fluent or a fluent the precondition fixes), or, since stage c2a, a pair literal or effect that breaks a rule of "Pair fluents in the event file", or, since stage c3a, a `place_event_types` entry that breaks a rule of "Place event types in the event file".
- **"the condition of ... reads SOMEOF.PAIRFL.2(patient), whose value the precondition fixes".** An event file's condition that the entry's precondition decides under the implications of pair literals (the stage c3b follow-up, Jon's ruling WM.68): an act's location literal fixes `SOMEOF` of the place true, a positive pair fixes `SOME` of its first and `SOMEOF` of its second entity true, a negated `SOME` or `SOMEOF` fixes the pair false, and `SAME` fixes both `SOME` literals true and the pair false. The effect would be unconditional or never applied, so the entry is refused; read a literal the precondition leaves open, or drop the condition (the chain example's rest act reads `SOME.PAIRFL.1(agent)`, the agent is near someone).
- **"the effect agent.BOOLFL.3 := 1 can never change the state".** `check_dynamics` found a drawn Boolean effect `:= v` on a fluent whose initial rate makes every entity `v` and that no effect sets to `not v` (Jon's ruling WM.70, stage c4a); the generator draws such an effect again, so this is a bug in the generator, not in the configuration. An event file's effects are not checked.
- **"the place event type PLACEEVENTTYPE.2 is written as 'act', but its record is a move".** A `definition.json` whose `place_kind` (stage c3b, WM.65) disagrees with the record, or lacks it where the place event type has dynamics; the file was edited, or written by another program. Regenerate it, or fix the key: a move has an effect that adds a pair of a location fluent, an act has none.
- **"the event file defines PAIRFL.4, but the world configuration's pair_fluents.count is 0".** Since stage c2b an event file's pair fluents must be among `PAIRFL.1` to `PAIRFL.<count>`; set `pair_fluents.count` to at least the file's highest label (`tiny_pairs.yaml` sets 4).
- **Few events in a world of needs.** A numeric literal `> t` on a fluent that nobody starts above and that drifts downward, with a small effect, is achievable but rarely true, so its event type is rarely legal. `world_stats.yaml` (`episodes.legal_share`) shows it; a positive drift, a `fixed` or `beta` initial distribution, or a larger `numeric_amounts` interval helps.
- **`taxonomy.config` is not found.** Paths in a configuration are read from the folder the command runs in. Run from the root of the repository, as the examples do.
