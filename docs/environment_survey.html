Semantic World · background review · checked 25 Sept 2026

Environment Survey

No existing environment can be adopted as Semantic World. Each candidate misses something we need: full 3D, a fully open stack, a propositional observation channel, language between agents, or support for both world regimes. So we build our own core and borrow heavily.

A real gap. No maintained, open simulator combines novel compositional object kinds, a taxonomy over those kinds, and a generated lexicon. Filling that gap is a contribution in its own right.

Recommended architecture

ModelsDeep RL agents, symbolic planners, Bayesian and other models, all in Python.
AdaptersThin Gymnasium (one agent) and PettingZoo (many agents) wrappers. PufferLib as an optional RL training harness.
Core APIPyO3 + maturin. A batch object steps many worlds per call. Returns NumPy arrays plus a symbolic state and query API for non-RL models.
Rust coreHeadless, using Bevy's ECS on its own. Compositional objects are entity hierarchies. Synchronous fixed-timestep stepping, one seeded RNG per world. Rapier physics for the generative world only.
ViewersState snapshots streamed over a websocket to a browser viewer (three.js, or Bevy compiled to WebAssembly). Rerun for debugging and replay.

Why Rust

Memory safety for a codebase touched by rotating students and RAs. Easy Python packaging with maturin. The core, the physics, and the viewer share one language. A C++ stack (flecs, Jolt, nanobind) is equally viable.

Alternative: Luanti

The fastest path to the survival world: open C++ voxel engine, headless server, Lua scripting, native multiplayer. Voxels fit the generative world badly, so it likely means two engines.

Main risks

Bevy's frequent breaking releases. The cost of a custom viewer. GPU rendering at scale. Determinism limits some physics speedups. Rust ramp-up for students.

What it offers us

Ideas to borrow, by workstream

Contracts and engine

  • One canonical symbolic state. Pixels, propositions, and text are all views of that state. ALFWorld, TextWorld
  • PDDL-compatible propositions. Off-the-shelf planners become symbolic baselines for free. Blocks World PDDL
  • Predicates over object states as the template for the propositional channel. BEHAVIOR BDDL, AI2-THOR
  • Entities and rules declared as data. Melting Pot
  • Symbolic, pixel, and text channels plus agent messaging. Alem

Survival world

  • Minimal need dynamics. Separate hunger, thirst, and fatigue counters; slower decay during sleep; day/night. We add temperature. Crafter
  • Multi-agent resources. Regrowth, depletion, respawning, and death. Neural MMO
  • Regional temperature from biome heat values. Luanti

Generative world

  • Sampled rule grammars linking features, parts, and kinds to capacities, with complexity and stochasticity as variables. XLand-MiniGrid
  • Part-level attributes ("the blorg with red arms"). Super-CLEVR
  • Compositional splits built into the generator. SCAN, gSCAN, PHYRE
  • Distractors that make every word necessary. ReaSCAN
  • Balanced questions and four question types. CLEVR, CLEVRER
  • The lexicon as a manipulation. English names give LLMs a head start from prior knowledge. Mystery Blocksworld, ScienceWorld
  • Word-learning task checklist. MEWL

Models and evaluation

  • Held-out partners at test time. Melting Pot
  • Compositionality metrics for emergent language. EGG
  • Similarity to children's response patterns, if developmental comparison becomes a priority. DevBench

Decisions this survey suggests

  1. Choose Rust for the core, unless there is a reason to prefer C++.
  2. Use one engine for both world regimes, rather than extending Luanti for the survival world only.
  3. Make the propositional layer PDDL-compatible.
  4. Design our own core API first, with Gymnasium and PettingZoo as adapters.
