## Engineering choices

Numbered here, and nowhere else (the change track logs no WM.E rows).

1. **`condition_kinds`** (follow-up 1 of stage b1) is read by `config.py` with the `weights` reader of the taxonomy's configuration nodes (`allowed=("feature", "fluent")`, at least one weight positive), kept on `EffectsConfig`, written by `resolved()` (so `config.yaml` records it), and listed in `data/world/default.yaml`. `_draw_condition` keeps the draw of stage b1 when the two weights are equal (`rng.integers(2)` over the two pools) and uses the weighted draw (`_draw`, which is `rng.choice` with probabilities) otherwise, with a comment that says why: the weighted draw reads the stream differently, so using it for the even split too would change every condition of the existing worlds. With the default, the draws are exactly those of stage b1, and the definitions are byte-identical (checked against the reference run). A world without static features (none in the examples) draws from the fluents alone, as before.
2. **The two shares** (follow-up 2) are `effects.conditional.share_of_drawn` and `effects.conditional.share_of_all` in `world_stats.yaml`. `_Dynamics` counts the effects a condition is drawn for (`condition_draws`: the effects of event-type features, once each, and the own effects of every event type without an explicit entry) and how many got one, on a field of `EventTypes` of its own, so that `fix_ups` keeps its keys; `world_stats` divides, rounded to six decimals as the other shares are. Nothing else in the run changes; the default world's two shares are under "Follow-ups" below.
3. **The tiers** are a `slow` marker, registered in `tests/conftest.py`, and two options of the same file: plain `pytest` deselects the marked tests, `pytest --slow` deselects the others, `pytest --all` keeps both; the summary counts what was deselected. A parametrized test over the worlds marks its `default` case with `pytest.param("default", marks=pytest.mark.slow)`, so that the same property runs on the tiny, deep, and still worlds in the fast tier and on the default world in the slow tier; a test that needs the default world alone carries the marker. The marker expression `-m slow` works too, but the options also deselect the other tier, which a marker expression on top of `addopts` would not do cleanly.
4. **The snapshot** is `tests/figures/snapshot.yaml`, written by `python -m semantic_world.figures snapshot` from the runs in `runs/` (and from worlds defined in memory for the baselines), with the figures of each run under `<name>.world` and `<name>.corpus` and the baselines under `baselines.<feature>.<name>`. The figures are read by `semantic_world.figures.world_figures` and `corpus_figures`, which the test and the command share: `world_figures` reads `config.yaml`, `world_stats.yaml`, `definition.json` (the identity, the conditional effects' expressions and their holders), `entities.csv` (their count), `taxonomy/categories_generative.csv` (the categories' count), and `derived/` (the mean, least, and greatest one-place capacity rate and two-place pair proportion, which `WORLD.md` quotes); `corpus_figures` reads `config.yaml` and `stats.yaml`. `tests/figures/test_figures.py` regenerates the tiny world and corpus in memory in the fast tier and the default ones in the slow tier, writes them to a temporary folder, and compares every figure; a mismatch prints each figure that moved. The taxonomy's golden hashes and the byte-identical tiny fixtures stay as they are: they are regression checks of the draws with commands of their own (`make_golden_hashes.py`, `make-fixtures`), and the snapshot holds figures, not hashes.
5. **The figures script** is the same module, `python -m semantic_world.figures guides [--check]`. A figure in a guide stands between `<!--figure:KEY|FORMAT-->` and `<!--/figure-->`, where `KEY` is the dotted path into the figures (`default.corpus.sentences`, `tiny.world.wrote_line`, `baselines.conditional_effects_off.default.rule_set_short`) and `FORMAT` an optional Python format specification (`,` for a thousands separator, the default for an integer; `d` for a plain integer, as a program's output prints it; `.3f`; `.0%`). The markers are HTML comments, which GitHub and every Markdown viewer hide. The script reads the runs in `runs/` and the snapshot's baselines, rewrites every marked figure, and prints each one that moved with its file and key; `--check` prints without writing and exits with 1 when something would move. The world's "wrote" line and its redraw notes are figures of their own (`wrote_line`, `redraw_notes`), so that a quick-start block is rewritten whole.
6. **Hand-written figures with dates.** The figures that no default or tiny stats file holds stay hand-written, each with the date of its run beside it: the run times (already dated), the two-place shares and densities of seeds 2 to 5 and the levers table in `WORLD.md` (the levers take half an hour; the seeds would take a minute, but their table also quotes stage a8's shares, which no run reproduces), the `simulate` output line in `WORLD.md`, the `relation_fact_share: 0` co-occurrence row from a 2,500-document run and the ambiguity recipe's count in `CORPUS.md`, and the word-form figures in `WORDFORMS.md`. No extra run folder is an input of the script, which keeps the script to the default and tiny runs.
7. **Parallel safety.** The corpus's word-form tests gave their word-form runs no `synthesis.cache_dir`, so they shared the default `runs/wordforms/cache`; they now use a cache beside the request in their temporary folder. No other test writes outside its temporary folder (the search found none); the two suites at once are checked at the end.
8. **What counts as a count of a run.** A figure that depends on the random draws of the default or tiny run: the numbers of entities, categories, sentences, tokens, scenes, pairs, statements, lexemes (which depend on the categories' count and on which event types get a word), rule terms, and identities; which event types were redrawn; which sets fill. A count that the configuration fixes (40 PROPERTY features, 20 one-place event types, 8 fluents, 1,000 statistics episodes, 17 function words, the names of the 41 test sets, 12 instances of the tiny taxonomy at 3 per leaf) is not a figure of a run, and the tests keep stating it, from the configuration or from the code's constants where that is cheap. The taxonomy's own tests, whose figures are of the taxonomy's example configurations and are covered by the golden hashes, and the word-form pipeline's tests (its own hashes of the example configurations' word tables) are left as they are.
9. **Bounds from the configuration.** A test of a rate states the configured rate and a margin of three standard errors of a binomial share over the number of draws it counted (`standard_error(share, count)` in the test file), and a test of an effect of a weight states that the effect exceeds three standard errors; where the realized share is the rate times a share the world sets (an event has a result only when it changed a fluent with a word; a description or a clause is drawn only when one can be said), the test states that the share is at most the rate and that two shares stand in the ratio of their rates, up to the margins. The two lowered bars are replaced this way: the result-rate bound (0.1 at the rate 0.3) by the ratio of the shares at 0.3 and 0.9 with their margins, and the `nec_none` margin (1.25) by a rise of more than three standard errors. The co-occurrence margin of 0.01 at 2,500 documents is dropped: the property of stage 6 is the sign of the difference, and the difference there (0.015 by words) is within the sampling error of a correlation over 741 pairs, so no margin can be derived; the test states the sign.

## The follow-ups of stage b1

1. **`event_types.effects.condition_kinds`** (ruling 1), a weight map over `feature` and `fluent`, default `{feature: 0.5, fluent: 0.5}`, read and validated like the other world keys (unknown kinds and all-zero weights are errors that name the field), written into `config.yaml`, and listed in `data/world/default.yaml`. With the default, the draw is the stage b1 draw (choice 1): the tiny and default worlds regenerated with the new code are byte-identical to the reference run made from `main` before the change, file for file, apart from `config.yaml` (the new key, and the provenance) and `world_stats.yaml` (the two shares below). `tests/world/test_world_conditions.py::test_the_two_settings_are_read_and_validated` covers the key, and `test_condition_kinds_weigh_the_kinds` (new) checks that `{feature: 1, fluent: 0}` gives static literals alone, `{feature: 0, fluent: 1}` fluent literals alone, and that the even split in another spelling (`{feature: 2, fluent: 2}`) gives the default world's conditions.
2. **The two shares** (ruling 2), in `world_stats.yaml` under `effects.conditional`: `share_of_drawn`, the share of the effects a condition was drawn for that got one, and `share_of_all`, the share of all effects of all event types that have one. In the default world they are 0.153846 and 0.308642: a condition was drawn for 52 effects (the 5 effects of event-type features, once each, and the 47 own effects of the event types), 8 of them got one (2 feature effects and 6 own effects), and the 2 feature effects are inherited by 19 event types, so 25 of the 81 effects are conditional. The stage b1 proposal counted "the 5 feature effects and the 76 own effects" as drawn; the 76 counted the inherited copies too, which no draw is made for. ## Jon's rulings on the open questions

Ruled on October 12, 2026, and recorded here; ruling 3 is logged as PR.2 in `docs/DECISIONS.md`, the others in this file alone. The follow-ups were built in stage b2 (`docs/proposals/2026-10-12-world-stage-b2-decisions.md`).

1. **Where the conventions' decision sits** (question 1): PR.1 stays in the new "Process" section.
2. **What counts as a count of a run** (question 2): counts that the configuration fixes (the number of features, one-place event types, function words, set names, tiny instances) may be asserted in tests, because they change only when the configuration or the code changes on purpose. Where it is cheap, a test derives such a count from the configuration rather than writing a literal. Counts that depend on random draws belong in the snapshot only.
3. **Byte identity when off** (question 3): world features keep the promise (with the feature off, every earlier output stays byte-identical, tested against the snapshot). Corpus features make no such promise: they share the space of a document, so turning one off reshuffles others, and designing around exact identity would constrain the corpus for no scientific reason. New corpus features still draw from their own streams where that is easy, because it helps review. When a study needs a paired comparison of corpus content, a filter tool that removes one kind of sentence from a full corpus will be built, as change-track work. (The full corpus promise is on Jon's longer-term to-do list, outside this repository.) Built as follow-up 1 of stage b2: the rule in `CLAUDE.md`, "Random streams for new features".
4. **The margin of the `nec_none` test** (question 4): three standard errors were preferred if the rise cleared them comfortably; it measures about two and a half, so the test keeps two, with a comment in the test that says why. Built as follow-up 2 of stage b2.
5. **The slow marks** (question 5): the world's interference tests over random tiny states (marked slow by their run time rather than by needing a default run) are core checks, so they return to the fast tier; the word-form audio tests stay slow, because they synthesize speech and need the speech extra. The fast tier runs on every core (`pytest -n auto`). Built as follow-up 3 of stage b2.
6. **The language-model example under load** (question 6): the example pins its thread count (`torch.set_num_threads(1)`) and its seed, so that its loss does not depend on what else is running. Built as follow-up 4 of stage b2.
