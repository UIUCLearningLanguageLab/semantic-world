### Reading of the scope

- **"The code's defaults follow `default.yaml`" (WM.63).** `PairFluentsConfig` defaults to `count: 0` and `locations: 0`; a world configuration without a `pair_fluents` block has no pair fluents, so every configuration in `data/` that does not set `count` above 0 is the world of stage c2a.
- **"A replaced pair fluent still consumes its draws."** The three draws of a pair fluent (symmetry, functional, initial rate) are made for every label from 1 to `count`, and then an override of `fluents.PAIRFL.<n>` or an event file's entry replaces the values, as `fluents.py` draws an overridden Boolean fluent's rate before replacing it, and as `numeric.py` does for a numeric fluent's drift.
- **"As numeric literals are (WM.E193)."** A pair literal, a pair effect, and a pair condition literal each replace a draw of the existing kind at the share, from a stream of its own, so that with the share at 0 nothing is drawn from the pair stream and the Boolean draws are those of the world without pair fluents.
- **"Where c2a's checks of an explicit entry raise an error."** In generation, every rule that c2a enforces on an explicit entry with an error becomes a redraw of the drawn literal, effect, or condition, counted in the statistics; the explicit checks and `check_dynamics` are unchanged.
- **"With the pair shares at 0 ... the preconditions, effects, and conditions of the existing event types are those of the world without pair fluents."** The derived fluents' rules may differ when pair literals are in the pool ("Determinism": the pool is larger), and a different derived rule can change which literals are achievable and so the fix-ups. The baseline of this off setting therefore sets `rule_weight` and `derived_rules` to 0 beside the shares, as the numeric recipe of `WORLD.md` sets `numeric_fluents.rule_weight` to 0, and the test compares the event-type records with those of the world with `count` 0 (see "Engineering choices").
- **"Tests of `tiny_full` belong to the fast tier."** The default-scale acceptance checks (the quota on seeds 1 to 5 of `default_full`, the figures of `default_full`, its baselines) are in the slow tier.

## Engineering choices made while building

Numbered for `docs/DECISIONS.md` (WM.E270 to WM.E285). Each is Claude Code's choice inside the stage's scope.

1. **The configuration.** `PairFluentsConfig` reads the `pair_fluents` block (`count`, `locations`, `symmetry`, `functional_rate`, `initial_rates`, `literal_kinds`, `same_rules`, `derived_rules`, `rule_weight`, `fluents`) with the code's defaults of WM.63 (`count` 0, `locations` 0) and the specification's other values; `locations` must be 0 until stage c3; `same_rules` is read and validated and does nothing without location fluents; an override `fluents.PAIRFL.<n>` may give any subset of `symmetry`, `functional`, and `initial_rate`, each replacing that value alone (the pattern of the numeric overrides), and must name `PAIRFL.1` to `PAIRFL.<count>`; the quota `derived_rules` applies to the first that many derived fluents, all of them when the world has fewer, so that it never constrains the fluents (with `fluents.count: 0`, the off setting of the fluents, the quota is empty rather than an error). `event_types.preconditions.pair_share` and `event_types.effects.pair_share` (default 0.2) and the kind `pair` of `condition_kinds` (default 0.2, used only when the world has pair fluents, so that a world without them draws its conditions as before) are read beside the numeric settings. `default.yaml` lists every new key; `tiny_pairs.yaml` sets `count: 4` and every pair draw to 0 (WM.63).
2. **The drawn profiles.** `generate_pair_fluents` draws from `world:pair_fluents` in label order, three draws per pair fluent from `PAIRFL.1` to `PAIRFL.<count>` (the symmetry by `_draw` over `symmetry`, one draw against `functional_rate`, the initial rate uniformly from `initial_rates`), and an override or an event file's entry replaces the drawn values after every draw is made, so that a replaced pair fluent shifts no other pair fluent's draws (as `fluents.py` draws an overridden Boolean fluent's rate before replacing it). An event file's entries must be among `PAIRFL.1` to `PAIRFL.<count>` (a label above the count is a `ConfigError` naming the file and the count) and need not be contiguous, because the pair fluents they do not name are drawn (c2a's rule of no gap goes, since the gaps are filled). The initial pairs come from `world:pair_initial` by c2a's procedure. `tiny_pairs.yaml` keeps stage c2a's rule-set identity.
3. **The streams.** `world:pair_preconditions`, `world:pair_effects`, and `world:pair_conditions` follow `world:pair_initial` in `STREAM_NAMES`; a never-legal event type's redraw draws its pair replacements from the part `world:pair_preconditions:<label>`. Every configuration in `data/` that does not set `pair_fluents.count` above 0 draws from none of them, and its world is byte-identical to stage c2a's (the snapshot's identities and baselines, which did not move). Stage c3's `world:place_dynamics` and `world:habitats` follow.
4. **The pair literal draw.** `random_pair_literal` in `event_types.py` draws the kind by the weights of `literal_kinds` among the kinds the event type can take (`same` needs a functional pair fluent that is not symmetric, on which `SAME` could never hold, c2a's open question 3; a one-place event type takes `some` alone), the pair fluent uniformly among those the kind allows, then for `pair` which role comes first, for `some` `SOME` or `SOMEOF` and then the role, nothing more for `same` (its two roles are a set), and the polarity, each uniformly. In a precondition the replacement at `pair_share` from `world:pair_preconditions` comes after the numeric replacement of WM.E193, so a numeric literal can be replaced too, and a candidate that is not achievable, that fills a slot the precondition already fills (by what it names), or that names what a pair condition of the event type names or fixes a pair condition's value is drawn again up to `MAX_TRIES`, after which the drawn literal is kept (as the numeric replacement keeps the Boolean literal); `pair_fluents.fix_ups` counts the draws against the share, the replacements, the ones that kept the drawn literal, and the candidates drawn again.
5. **Slots by what a literal or effect names.** The drafts of the dynamics key every literal and effect by `_literal_slot` (`(role, fluent)` for a Boolean or numeric literal, `pair_literal_key` for a pair literal) and `_effect_slot` (`(role, fluent)`, or the pair written, both directions of a symmetric pair one slot) in the resolution of contradictions and duplicates, the own-literal and own-effect sets, the empty-effect and unachievable-literal fix-ups, and the eligibility of effects for a condition, so that the rules of WM.E261 hold in generation as they hold for an explicit entry.
6. **Pair effects and their fix-ups.** A pair effect replaces an effect drawn over two roles (an own effect of a two-place event type, or an event-type feature's effect, which only two-place event types inherit) at `pair_share` from `world:pair_effects`, after the numeric replacement: the pair fluent, the direction, and the value each uniformly (`random_pair_effect`). In the fix-up rounds an add whose precondition requires the pair or a delete whose precondition requires its absence is empty (an own effect drawn again, an inherited one dropped, with the Boolean counts), and the new `fix_compiled_contradictions` drops an inherited add, or draws an own add again, whose compiled literals (F4) contradict the precondition (counted under `pair_fluents.fix_ups`), so that `compile_profile_literals` appends the compiled literals after the rounds with no contradiction left; a drawn draft that still had one would be a `WorldError`, and none was in any run.
7. **Pair conditions.** A condition literal of the kind `pair` is drawn by the procedure of choice 4 from `world:pair_conditions` over the roles of the event type, when the world has pair fluents and the kind can be drawn for the event type (a one-place event type needs `some` with a positive weight); `_condition_ok` draws the condition again when a pair literal is not achievable, is the pair the effect itself writes (c2a's open question 4), is drawn twice, names a pair or row a holder's precondition (compiled literals included) names (c2a's exact reading), or has a value a holder's precondition fixes under the implications of choice 8, each rejection counted by its reason. An add on an asymmetric or functional pair fluent is not a candidate for a condition (F4): no share draw is made for it, it is left out of the effects a condition is drawn for, and `adds_kept_unconditional` counts it; this reading of "redrawn" draws nothing that would be rejected every time. An explicit event file keeps stage c2a's exact rule.
8. **The implications of item 6** (`fixed_pair_literals`), by `pair_literal_key` with a value: a positive `PAIRFL.k(x, y)` fixes `SOME.PAIRFL.k(x)` and `SOMEOF.PAIRFL.k(y)` true, for a symmetric pair fluent also `PAIRFL.k(y, x)`, `SOME.PAIRFL.k(y)`, and `SOMEOF.PAIRFL.k(x)` true, for an asymmetric one `PAIRFL.k(y, x)` false, and for a functional one `SAME.PAIRFL.k(x, y)` false (the one partner of `x` is `y`, which is not its own partner); `NOT SOME.PAIRFL.k(x)` fixes `PAIRFL.k(x, y)` and `SAME.PAIRFL.k(x, y)` false (for a symmetric pair fluent `PAIRFL.k(y, x)` too, the same pair); `NOT SOMEOF.PAIRFL.k(y)` fixes `PAIRFL.k(x, y)` false (for a symmetric one, where the column is the row, `SAME` too); `SAME.PAIRFL.k(x, y)` fixes both `SOME` literals true and `PAIRFL.k` false in both directions (the shared partner is a third entity, and `k` is functional); a negative pair literal, a positive `SOME` or `SOMEOF`, and a negative `SAME` fix nothing beyond themselves. A drawn pair condition with one of these keys is drawn again (`pair_conditions_rejected_fixed`). The rule is not applied between the literals of one precondition (open question 2).
9. **The redraw of never-legal event types.** `redraw_preconditions` takes the pair fluents and the parts `world:pair_preconditions:<label>`: a redrawn own literal is replaced by a pair literal at `pair_share` by the procedure of choice 4 (`_redraw_pair`), achievable, in a free slot, leaving the event type's pair conditions as conditions, and not making an own pair effect empty; the compiled literals and the inherited literals are kept keyed by what they name (stage c2a keyed the compiled ones by their text, which let a redrawn literal contradict one); and the enabling draw's produced values leave pair effects out (stage c2a's redraw could draw a Boolean literal on a pair fluent from an explicit pair effect, which no world of c2a showed because its explicit event types fix their preconditions; seeds 15 and 17 of `tiny_full` showed it).
10. **Derived rules over pairs.** `fluents.py` offers `SOME.PAIRFL.k` and `SOMEOF.PAIRFL.k` of every pair fluent between entities (`PairRuleInput`) in the input pool at `rule_weight`, and leaves them out when the weight is 0, as numeric thresholds are left out at weight 0, so that with the weight and the quota at 0, or no pair fluents, the pool reads `world:fluents` as before (review point 3); the first `derived_rules` derived fluents in layer order draw their rules first, each drawing its arity as the others do (raised to 2 when it comes out as 1, so that the rule reads a fluent of the layer below and a pair literal), a fluent of the layer below first, then one pair literal uniformly among them, then the rest from the pool (where a pair literal weighs at least a fluent for a quota rule with the weight at 0, so that the rest can still read one); the pair literals stand last among a rule's inputs, `SOME` before `SOMEOF`, by pair fluent, as `Var` atoms (the keys `build_definition` already turns into entity-scope literals); `derived_initial_values` reads them from the initial pairs; `FluentRule.pair_inputs` names them.
11. **The statistics.** `world_stats.yaml` gains the `pair_fluents` block of the specification as built (`count`, `by_symmetry`, `functional`, `fluents` with each profile, rate, and initial pairs, `initial_pairs`, `precondition_literals` by kind, role, polarity, and kind of event type and from features, `compiled_literals` by origin, `effects` by value, role, kind of event type, and pair fluent and from features, `condition_literals` by kind and role, `rules_reading_a_pair_literal`, `fix_ups` from `EventTypes.pair_stats`, and `pair_changes_per_event`), and `episodes` gains `pair_changes_per_event`, both written only when the world has pair fluents, so that every other world's statistics and figures are as before; `mean_changes_per_event` keeps counting Boolean changes alone.
12. **The figures.** `figures.py` reads the `tiny_full`, `default_full`, and `tiny_pairs` worlds into the snapshot beside `tiny` and `default` (no corpus runs on them until c4; `tiny_pairs` is there so that its identity is tested by the snapshot, as the stage prompt asks), computes the off-setting baselines for the four worlds without an event file (`BASELINE_NAMES`; the off setting of pair fluents would refuse `tiny_pairs`'s event file), adds the off settings `pair_fluents_off` (`pair_fluents: {count: 0, locations: 0}`) and `pair_dynamics_off` (the pair shares, the `pair` weight, `rule_weight`, and `derived_rules` at 0), reads the `pair_fluents` block into a `pair_fluents` figure only when the world has one, and names the pair fluents in the `wrote_line` figure as `define` does. The reading of "Determinism" behind `pair_dynamics_off` is under "Reading of the scope": the weight and the quota are part of the off setting because a different derived rule can change the fix-ups of the preconditions; the test compares the event-type records and the rules with those of the world with `count` 0.
13. **The configurations.** `data/world/tiny_full.yaml` is `tiny.yaml` plus `pair_fluents: {count: 2}`; `data/world/default_full.yaml` is every setting of `default.yaml` with `pair_fluents.count: 4` (the two files differ in the name, the comments, and the count alone, and a test checks it against the resolved configurations); their runs live in `runs/world/` beside the tiny and default runs, and `WORLD.md` quotes `default_full`'s figures by the script in a section "The full worlds".
14. **The fixtures.** The generated fixtures of `tiny_full` (`tiny_full_seed1` to `tiny_full_seed4`, `tiny_full_illegal`, `tiny_full_interference`) are committed beside the tiny fixtures, which did not change (`make-fixtures data/world/tiny.yaml` gives the committed files byte for byte); a test regenerates the `tiny_full` fixtures byte for byte, and the identity test of the tiny fixtures leaves the `tiny_full_` files to their own test.
15. **The profile check.** `profile_violations` tests each profile over the whole matrix with `any` before locating the first violation, because the runtime checks every profile after every step of every episode; the result is unchanged. The growth of the define time of `default_full` is flagged under "Run times".
16. **The tests.** `tests/world/test_world_pair_generation.py` checks the acceptance properties on every seed of `tiny_full` that defines (seeds 1 to 5, 8, 10, 13, 15, 17 to 20; on the others the tiny place taxonomy cannot place a superordinate within its similarity bound, as `tiny` fails on the same seeds) in the fast tier and on seeds 1 to 5 of `default_full` in the slow tier; forces an asymmetric functional and a symmetric functional pair fluent with every share at 1 (`FORCED_PROFILES`), so that the compiled literals, the `SAME` rule, the adds that keep no condition, and the redraw of contradicting compiled literals are exercised whatever seed 1 draws; checks each pair share against a binomial bound (three standard deviations of the share over the pooled draws, plus one draw) over the pooled draws of the `tiny_full` seeds and of seeds 1 to 5 of `default_full`, using the counts of draws against the share that `pair_fluents.fix_ups` records; and checks the implications of choice 8 literal by literal.

## The redraws of item 6, with their counts

The generator rejects a drawn pair condition (and draws the condition again, under `fix_ups.conditions_redrawn`) for three reasons, counted apart under `pair_fluents.fix_ups`: `pair_conditions_rejected_named` (it names a pair or row the precondition names, c2a's exact rule), `pair_conditions_rejected_fixed` (its value is fixed by the precondition under the implications of choice 8), and `pair_conditions_rejected_other` (not achievable, the pair the effect writes, or drawn twice in one condition). An add on an asymmetric or functional pair fluent keeps no condition and is counted under `adds_kept_unconditional`; the contradicting compiled literals of an add are counted under `pair_effects_redrawn_compiled` and `pair_effects_dropped_compiled`.

| World | Pair conditions drawn | Rejected: named | Rejected: fixed | Rejected: other | Adds kept unconditional | Adds redrawn or dropped for their compiled literals |
| --- | --- | --- | --- | --- | --- | --- |
| `default_full`, seed 1 | 3 | 0 | 0 | 0 | 0 | 0 |
| `default_full`, seeds 1 to 5 together | 19 | 0 | 0 | 1 | 10 | 0 |
| `tiny_full`, seed 1 | 0 | 0 | 0 | 0 | 0 | 0 |
| `tiny_full`, forced profiles, every share at 1 | 5 | 0 | 1 | 1 | 2 | 3 |

At the default shares the implications of item 6 rarely bite (0 of 19 pair conditions over five seeds of `default_full`), because a pair condition and a pair literal of the same precondition on the same pair fluent are both rare; with every share at 1 on the forced tiny world one condition in five is drawn again for it. On seed 1 of `default_full`, 7 of the 43 draws against the precondition share replaced a literal (two candidates were drawn again), 6 of the 33 draws against the effect share replaced an effect, and no replacement failed to find an achievable pair literal; over seeds 1 to 5, 39 of 221 literal draws and 30 of 177 effect draws, within the binomial bound of the share 0.2 that the tests state.

## Open questions

None of these changes the design; each is recorded for Jon's eye.

1. **Pair fluents that never hold.** Under the specification's `initial_rates` (`[0.0, 0.05, 0.2]`) a third of the pair fluents start empty, and a pair fluent with the rate 0 holds a pair only after some add; with the value of a pair effect drawn uniformly, and about six pair effects in the default world, a pair fluent can draw deletes alone. On seed 1 of `default_full` two of the four pair fluents (`PAIRFL.1`, `PAIRFL.3`) never hold between any two entities, though six event types delete a pair of `PAIRFL.1` and ten two-place event types inherit `NOT SOME.PAIRFL.3(agent)`, which is always true; on seeds 2 to 5 every pair fluent with the rate 0 is added by some event type. Both are frequencies of the world ("A principle for defaults"), and the stage leaves them; a setting that keeps every pair fluent alive would be `initial_rates` without 0, or a rule that a pair fluent with the rate 0 gets at least one add (a quota of the kind of `derived_rules`).
2. **Redundant pair literals within one precondition.** The rule of item 6 (a condition fixed by the precondition is drawn again) is applied to conditions, as the stage prompt says, not between the literals of one precondition: `EVENTTYPE2.3.3` of seed 1 holds `NOT SOME.PAIRFL.3(agent)` and `NOT PAIRFL.3(agent, patient)`, the second implied by the first (they name different things, so c2a's rule allows both). Applying `fixed_pair_literals` to a drawn precondition literal against the literals already kept would remove such redundancy; it would change the draws of `default_full`.
3. **The quota `derived_rules` is capped, not an error**, when the world has fewer derived fluents (choice 1), so that `fluents: {count: 0}` stays a valid off setting of the full worlds. A configuration error would be stricter.
4. **An add on an asymmetric or functional pair fluent keeps no condition** by not being a candidate (choice 7), rather than by a condition drawn and rejected; the share draw is not made for it, so on a world with many such adds fewer effects are conditional than `conditional_share` would give. The alternative, drawing and rejecting, would spend the draws without changing the outcome.
5. **The define time of `default_full`** is 1.6 times the default world's (above), in the runtime's work over pairs, which every episode of a world with pair fluents will pay (the corpus's scenes in c4 too). A representation of rows and columns as single keys in the read sets, instead of every pair, would cut most of it without changing any output; it is change-track work on the runtime of c2a, if wanted.
6. **The effect share counts every effect draw of a two-place event type**, including the draws that a forbidden slot rejects, so the realized share of pair effects among the kept effects is near 0.2 but the counter is of draws. The precondition share counts likewise. The tests check the counters.
7. **The pair weight of `condition_kinds` in `default.yaml`** is listed at 0.2 though the default world has no pair fluents, because `default.yaml` lists every parameter with its value (WM.63); it is used only when the world has pair fluents.

## Notes for stage c3

What the builder of locations (location fluents, habitats, the dynamics of place event types, `SAME` and `SOMEOF` on location fluents, the quota `same_rules`, places in episodes, histories with places, the location statistics) must know:

1. **The configuration.** `PairFluentsConfig.locations` is read and must be 0; c3 lifts the check and gives `tiny_full.yaml` and `default_full.yaml` (not `tiny.yaml` and `default.yaml`, WM.63) `locations: 1`; the code's default stays 0 until c4. `same_rules` is read (default 2) and unused. `PlaceEventTypesConfig.move_share` and `PlacesConfig.habitat_strength` are read since c1.
2. **The streams** `world:place_dynamics` and `world:habitats` go after `world:pair_conditions` in `STREAM_NAMES` (the specification's "Determinism" lists them before the pair streams of c2b; the as-built note gives the order of creation).
3. **The pair fluents.** `generate_pair_fluents` draws `count` pair fluents between entities; the location fluents take the labels after `count` (WM.54) with the fixed profile `general`, functional, total, toward places, and `PairFluents.initial_pairs` holds one `(entities, entities)` matrix per fluent, which c3 extends with `(entities, places)` matrices for location fluents (`profile_violations` handles a non-square matrix and the total profile; `_check_state` of the runtime checks the square shape). `pair_rule_inputs` in `fluents.py` leaves total pair fluents out of the derived rules' pool (`SOME` of a location fluent is constant), and `random_pair_literal` draws over `pair_fluents.fluents` as a whole: c3 must keep location fluents out of the draws of entity event types except where the specification lets `SAME` and `some` read them, and give place event types their own draws (`pair` and `same` on location fluents, `some` on the agent's pair fluents between entities or `SOMEOF` of the place).
4. **The quota `same_rules`** draws from its own part of `world:pair_preconditions` among two-place event types for which some able binding can satisfy the rest of the precondition; `_Dynamics.able_bindings` and `_static_satisfiable` give the able bindings; the literal is `SAME.PAIRFL.k(agent, patient)` on a location fluent, keyed by `pair_literal_key` like every other, and `fixed_pair_literals` already lists what a positive `SAME` fixes.
5. **Moves and acts.** A move's effect is an add on a total functional pair fluent (the replacement of the old pair is c3's, in `apply`); its compiled literal `NOT PAIRFL.k(agent, patient)` has the origin `move`, which `compiled_literals` (origin `profile`) does not give: c3 adds the origin and keeps `add_compiled_literals`' rule that a literal already present is not added twice. `keeps_no_condition` would keep a move's add unconditional, which F4 requires. `fix_compiled_contradictions` runs in the fix-up rounds for every draft with a pair effect, place event types included once they have effects.
6. **The achievability of literals on location fluents**: `pair_literal_achievable` reads the initial rate and the adds and deletes; a location fluent has no rate (every entity is somewhere) and never a delete, so `SAME` on it is always achievable and `SOMEOF` of a place needs the habitats; c3 gives the function a case for total pair fluents.
7. **The statistics.** `pair_fluent_stats` counts over `event_types.leaves` (entity event types); place event types are not leaves. The `by_symmetry` counts and the `fluents` rows will cover location fluents; the location statistics of the specification (moves, acts, the two-place share counting place event types apart, the concentration of habitats) are new keys, written only with locations.
8. **The figures and the snapshot.** `WORLD_CONFIGS` and `BASELINE_NAMES` in `figures.py` hold the full worlds; c3 regenerates their runs and the snapshot (their identities will move with the location fluents), and may add a `locations_off` setting (`pair_fluents: {locations: 0}`) with its baselines.
9. **The fixtures.** `make-fixtures data/world/tiny_full.yaml` regenerates the `tiny_full` fixtures, which will move with the location fluents; the tiny fixtures must not. `initial_places` in the fixture format waits for c3.
10. **The tiny world's place requirements** (WM.62) are changed in c3 so that every tiny place requirement reads the place: in `tiny.yaml` as the ruling says, which `tiny_full.yaml` must copy (the two files differ in the `pair_fluents` block alone, and a test checks it).
