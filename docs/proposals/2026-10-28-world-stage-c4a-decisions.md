### Reading of the scope

- **"Its initial rate makes every entity v."** The Boolean rule reads the fluent's initial rate, as ruling 1 reads a pair fluent's (`initial_rate == 0.0`): an effect `:= 1` is dead when the fluent's rate is 1 and no effect sets it false, and an effect `:= 0` when the rate is 0 and no effect sets it true. The rate, not the drawn values, because `scene.initial: redraw` draws the values again at the rate, so a fluent of rate 1 is true of every entity in every episode, while a fluent of rate 0.8 whose twelve tiny entities all drew true can be false after a redraw. The literal rule of stage a2 reads the drawn values (`initial_present`), as before.
- **"An explicit event file is not checked."** `check_dynamics` holds the rule for every event type whose effects the generator drew: an event type with explicit effects is skipped, as `fix_dead_deletes` skips a draft with explicit effects. `check_place_dynamics` likewise skips an explicit place entry. The effects an explicit entry gives are what the file says.
- **"No effect anywhere in the world"** counts every effect, the place event types' included (WM.66), as the dead-delete rule counts every add.
- **"The code's defaults follow default.yaml."** `pair_fluents.count` 4, `pair_fluents.locations` 1, `places.habitat_strength` 2, and `place_event_types.density` `[0.05, 0.5]`. A configuration with `places: null` and no `pair_fluents` block would then fail (location fluents need places), so with `places: null` the default of `locations` is 0, as the default of `place_event_types` is none without places.
- **"tiny_pairs.yaml and tiny_place_chain.yaml keep their rule-set identities."** Each gets, explicitly, `places.habitat_strength: 1` and `place_event_types.density: null`, and keeps its explicit `pair_fluents` settings; `tiny_pairs.yaml` gets `locations: 0` too. Their identities are checked against the reference run.
- **"The corpus says nothing about pair fluents, places, ... in this stage."** No concept of the lexicon changes, so the word-form requests change only if the documents' function-word frequencies or inflected forms change; the request's `lexemes` list is the test of "unchanged".
- **"An event of a place event type is never narrated."** The planner skips it where it iterates a scene's events, and so do the relative clauses that report earlier events; `Truth.events_of` keeps every event of the history, so that a time point's index and `_first_step` are those of the history, and every reader that names an event's event type skips a place event.
- **"A causal statement never states a pair literal."** The enumeration never offers one (it runs over the base and numeric fluents with words), `has_entry` and the oracle's `causal` compare a precondition literal by its fluent, which is never a pair fluent of a statement, and a condition with a pair literal gives no `Condition`, so a conditional effect with a pair condition makes no statement, and its unconditional form is never true (`effect_matches` compares the conditions, and None matches nothing).

9. **A narrative drawn again takes new scenes (WM.E334).** The full check list found a deadlock of the planner that the new worlds exposed: a scene is drawn from the part of `corpus:scenes` named by its label, and the number of events at a step is a Poisson draw from that part before anything depends on the seed, so a scene with no event comes back with no event whatever the seed; since stage c4a a scene can also have only moves and acts, which no word reports. A draft with nothing to say is drawn again, but its scene numbers are not consumed, so a configuration whose narratives have one scene each (the test `test_an_entity_narrative_has_two_to_five_scenes` sets `entity.scenes: 1`) drew the same empty scene a hundred times and raised `CorpusError` ("no document with a sentence could be made for DOC.34"). The default corpus escapes the trap only because a retry can draw an encyclopedic document or an entity narrative of several scenes. Now the k-th redraw of a narrative takes its scenes from the parts `SCENE.<n>.REDRAW.<k>`, so the first draft of every scene number is drawn as before, and a rejected narrative's number gets a new scene. The planner counts the rejected drafts in `redrawn_drafts`, written to `stats.yaml` as `documents.redrawn_drafts`: 0 in the tiny corpus and 29 in the default corpus of 10,000 documents. Keeping a rejected draft's scenes instead (so that the number is consumed) was not chosen: the scenes of the run would then include scenes no document mentions, which the truth would know, and the test sets' law-like marks read the truth's scenes. The change alters the corpora from the first redraw on, so the tiny and default corpora were regenerated once more after it, and their figures in the snapshot moved again.

## What the corpus skips or filters

Every place where the corpus or the oracle steps around a pair fluent, a place, or a place event type in this stage, so that stage c4b can take them up one by one:

1. `World.event_names` gives a place event type no name; through it `Truth.verb_names`, `Facts.event_names`, `happened`, and the event-level forms skip place events (`world.py`, `propositions.py`, `facts.py`).
2. The planner's narrative skips an event with `SceneEvent.place`, and its relative clauses report no earlier place event (`planner.py`, `_narrative` and `earlier`).
3. `Planner._result` skips a change on a pair fluent; a result sentence states Boolean and numeric changes only (`planner.py`).
4. `condition_of` returns no `Condition` for a condition with a pair literal, and `effect_matches` is false for a pair effect and for an effect under a pair condition; so no causal statement, conditional or unconditional, is made for them (`propositions.py`).
5. `Truth.has_entry` reads no pair literal as a precondition entry, so no precondition statement states one (`propositions.py`).
6. `Facts._conditional_report` counts a skipped effect under `pair_condition` or `pair_effect` (`facts.py`; `stats.yaml`, `causal.conditional_effects.unstated`). ## Open questions

1. **The function-word order of the word-form requests.** The requests list `function_words` by frequency in the documents, and that order moved with the documents (in the tiny request, `can` and `not` and `it` and `with` swapped and `that` two ranks lower; in the default request, `become` four ranks lower and `all` and `than` swapped), while the lexemes, inflections, affixes, and meanings are byte-identical. The pipeline assigns the function words' forms in that order, so a rerun of `wordforms all data/wordforms/corpus_default.yaml` would give some function words other forms than the existing run of October 15, 2026. The stage rendered with the existing word forms, as the prompt says, and `render` matches them by gloss, so the rendering is consistent. Should the request list the function words in a fixed order (the lexicon's), so that a change of the documents never changes the forms, or should the word forms be remade in stage c4b, where the lexemes change anyway and the pipeline must run?
2. **The test subject of the earlier stages.** The world tests of stages a1 to c1 now define the tiny world with the phase (c) settings off (`world_support.py`), so that they test what they tested, and the corpus tests' written worlds do the same. The alternative, running every earlier test on the new tiny world, would loosen some bounds (the pairs change which events are legal and which effects fire). Is keeping the earlier subject right, or should the earlier tests move to the full tiny world as stage c4b adds the pairs to the corpus?
3. **The counts of pair changes, moves, and acts in `stats.yaml`.** `mean_changes_per_event` counts Boolean and numeric changes only, and the scenes' place events are not counted anywhere in the corpus's statistics. The counts belong to stage c4c by WM.71; should c4b add `place_events` and `pair_changes` to the scenes' statistics earlier, since its narratives will state moves?
