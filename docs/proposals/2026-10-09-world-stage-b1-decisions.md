### Reading of the scope

- "**A conjunction of one or two literals over the binding**" is read as one or two condition literals, each naming a role of the event type and a symbol that is a static feature (a PROPERTY or PART feature, free or determined) or a Boolean fluent (base or derived), with a value. Capacities (`CAN.`, `CANBE.`) and scalar thresholds are not condition literals in this stage: a threshold literal is numeric, and waits for stage b2 with the numeric fluents.
- "**Non-interference counts what a condition reads**" is read with the writes unchanged: every effect of an event counts as a write of its fluent, whether or not its condition holds in the state, so two events whose conditional effects write the same fluent of one entity interfere whatever their conditions, and an event that writes what another event's condition reads interferes with it. The reads of an event are its precondition literals and its effects' condition literals that name a fluent, each through the cone of a derived fluent; a static literal reads nothing that an event can write. Judging the writes by the state would also keep the step order-independent, but the static judgment is the one a policy can make before it chooses the events, and the one the Rust runtime can make without evaluating conditions twice.
- "**A condition must be satisfiable together with the event type's requirement and precondition**" is read as: some able binding of the event type satisfies the condition's static literals; no fluent literal of the condition names a fluent of a role that the precondition names (the same value would make the condition redundant, so the effect would be conditional in name only, and the opposite value would make it never fire); and each fluent literal's value is achievable (some entity starts with it, or some effect produces it), as a precondition literal's is. An inherited condition (one on an event-type feature's effect) must be satisfiable for every event type that keeps the effect.
- "**An effect is empty when its precondition and its condition together already require the value it sets**": a condition literal on the effect's own fluent and role with the effect's value is rejected; the opposite value is allowed, because the effect then fires exactly when it changes something.
- "**Byte-identical with `conditional_share: 0`**": `definition.json` and `entities.csv` are byte-identical to the reference; `config.yaml` gains the two new keys and the new stream's seed, which is provenance; `world_stats.yaml` gains the new counts, which are zero.
- "**Report how many causal statements the default world loses**": the number of true causal statements of the default world (`Facts.causal_statements`) in the a8 reference against this stage's run, and the number of effects that became conditional.

## Engineering choices made while building

Numbered for `docs/DECISIONS.md` (WM.E174 and following). Each is Claude Code's choice inside the stage's scope.

1. **The condition literal and the record.** `dynamics.ConditionLiteral(role, symbol, value)` names a static feature (`PROPERTY.<n>` or `PART.<n>`, free or determined) or a Boolean fluent (`BOOLFL.<n>`, base or derived) of one role; its kind (`feature` or `fluent`) follows from the symbol. `Effect` gains `condition`, a tuple of literals, empty for an unconditional effect. The record of a conditional effect gains one key, `condition: {"literals": [{"role", "kind", "symbol", "value"}, ...], "expression": "<the conjunction>"}`, and its `expression` becomes `when <condition> then <assignment>`; an unconditional effect is written exactly as in phase (a), with no `condition` key, so the identity and the files of every existing world are unchanged (checked: `conditional_share: 0` gives the a8 definitions of the tiny and default worlds byte for byte, rule sets `bd02c67e7286` and `123a4a6eb9f3`). The `kind` is written although the symbol table implies it, so that the Rust runtime can read a literal without a lookup. The definition format's version and the fixture format's version stay 1: the key is additive and absent when empty.
2. **The loader** (`definition.py`) reads a condition and refuses a literal whose role the event type lacks, whose `kind` disagrees with the symbol (a `feature` literal must name a `property` or `part` symbol, a `fluent` literal a `fluent` symbol), or whose symbol is unknown, and a condition that names a symbol twice. `EventTypeRecord.effects` carry their conditions, so the corpus's `Truth` reads them from the same records as before.
3. **The runtime.** `apply` judges every condition in the step's starting state, before any effect of the step (`_fired`: a static literal from the cached static facts, a base fluent from the state, a derived fluent from `derive` over the bound entities), and writes the effects whose conditions hold. The writes an event counts for non-interference are every effect's, whether or not its condition holds in the state (`_writes` is unchanged), so two events whose conditional effects write one fluent of one entity interfere whatever their conditions, and a policy can judge interference before it knows the state's effect on the conditions. The reads are the precondition literals and the fluent literals of every condition, each through the cone of a derived fluent (`_reads_by_reader`); a static literal reads nothing an event can write. The interference error names the reader: "which the precondition of ... reads" or "which a condition of ... reads". `fired_effects(definition, state, event)` is new, for callers that want to know what an event writes in a state.
4. **The brute-force evaluator** (`fixtures.BruteForce`) gets the same semantics written apart: `condition_holds` by truth-table lookup for a derived symbol and by the entities table or the state for a base one, `fired` for the effects that apply, `reads` with the condition literals' cones, and `writes` unchanged as the potential writes. `check_fixture_brute` and the generated fixtures use them. Histories need no change: `_event_changes` and `replay` already read the recorded changes against what the step changed, and `replay` checks that every recorded change is to a fluent the event may write.
5. **The two settings** `event_types.effects.conditional_share` (0.2) and `event_types.effects.condition_literals` (`{1: 0.7, 2: 0.3}`) are read by `config.py` with the specification's defaults; a weight on 0 literals is an error. `data/world/default.yaml` lists them, and `data/world/tiny.yaml` keeps the defaults implicitly, so the tiny world gains conditional effects too.
6. **A stream of their own.** The conditions are drawn from `world:conditions`, a new stream after `world:effects` in the stream table, so that `config.yaml` records its seed. They are drawn after every other draw and fix-up of the dynamics (`_Dynamics.draw_conditions`, the last step of `run` before the explicit checks), so that with `conditional_share: 0` nothing is drawn and every other draw is the same as before the stage. The order of the draws: the effects of event-type features first, in feature order (an inherited effect brings its condition to every event type that kept it; the holders are the event types with the feature whose effects still hold the feature's effect and whose effects are not explicit), then each event type's own effects, in the order of its effects. For each effect one draw against the share, then the number of literals from `condition_literals`, then for each literal the role, the kind, the symbol, and the value.
7. **The kind of a literal** is drawn with an even chance of a static feature and a fluent, and the symbol uniformly within the kind; the role uniformly among the event type's roles (both roles for a feature's effect); the value uniformly. A uniform draw over the pool of all symbols was tried first: the default world has 80 static features and 8 fluents, so 17 of 17 literals were static and no condition read the state. An even split gives both kinds of condition, which the corpus's conditional causal statements (a modifier for a static condition, a relative clause for a fluent one) will need. Open question 1 below.
8. **The rules of a condition** (`_condition_ok`, with `check_dynamics` and the event-file checks enforcing the same): no symbol twice; a fluent literal is achievable (its value is some entity's initial value, or some effect produces it), names no fluent of a role that the precondition of any holder names (with the same value the condition would be redundant, so the effect would be conditional in name only; with the other value it would never fire), and never names the fluent the effect sets (with the effect's value the effect would change nothing; with the other value the fluent has the effect's value after the event either way, so the effect would guarantee what an unconditional one does while the corpus treats it as guaranteeing nothing); and some able binding of every holder satisfies the static literals, by the static side's able matrices (`Relations.matrix` for a two-place event type, the capacity column for a one-place one); a holder with no able binding at all (a never-able event type, which has no event) counts as satisfied, so that a feature's effect is not denied a condition because one event type of its branch can never occur (on seed 4 of the default world, four never-able event types of one branch made every draw for a feature's effect fail, 1,000 times, before this rule). The contradiction rule and the empty-effect rule of phase (a) keep their meaning: effects are still keyed by role and fluent, whatever their conditions, and an effect the precondition already requires is still redrawn before the conditions are drawn. A condition that breaks a rule is drawn again, up to `MAX_TRIES`, counted under `fix_ups.conditions_redrawn`; after the limit the effect stays unconditional and `conditions_dropped` counts it.
9. **Preconditions keep away from conditions.** `resolve_preconditions`, `fix_unachievable`, and `redraw_preconditions` never draw a literal on a role and fluent that a condition of the event type's effects reads (`condition_keys`), so a redraw of a never-legal event type's preconditions cannot make one of its conditions redundant or contradictory. Explicit effects' conditions are known before the preconditions are drawn; sampled conditions are drawn after them and avoid the preconditions themselves.
10. **Event files** accept `when <condition> then <assignment>` in `effects` (`Effect.parse`), and the file's conditions are validated like the sampled ones, with errors that name the file and the entry: an unknown feature or fluent, a role the event type lacks, a symbol twice, the effect's own fluent, a fluent the explicit or the sampled precondition fixes, an unachievable fluent literal, and a condition no able binding satisfies.
11. **The statistics.** `world_stats.yaml` gains, under `effects`, `conditional` (the total and by kind of event type) and `condition_literals` (the total, by symbol kind, by role, and from event-type features), and under `fix_ups` the counts `conditions_redrawn` and `conditions_dropped`. Achievability, `enabled_share`, the enabling graph, and the absorbing fluents count a conditional effect as producing its value, as the stage prompt asks.
12. **The hand world** gains two event types that are always able and legal, `EVENTTYPE1.4` (`when agent.PROPERTY.1 then agent.BOOLFL.2 := 1`) and `EVENTTYPE1.5` (`when agent.BOOLFL.3 then agent.BOOLFL.2 := 0`, a condition on the derived fluent whose cone is `BOOLFL.1` and `BOOLFL.2`), so that the twelve existing cases keep their hand-typed values (each gains the two always-legal event types in its `legal` lists) and five new cases cover a static condition that holds and one that fails, a fluent condition that holds and one that fails (the latter over three steps, with the condition judged in the starting state), and interference through a condition. The generated tiny fixtures are regenerated with the tiny world's conditional effects and still regenerate byte for byte.
13. **The corpus** treats an effect with a condition as no entry: `propositions.unconditional_effects` filters the record's effects in `Truth.has_entry` and `_evaluate_causal`, so `Facts.causal_statements` never lists a statement about a conditional effect, the truth tests judge it false (its grounding shows `with_entry` below `event_types`), and a category statement holds only when every leaf has the entry unconditionally. The oracle's `entries` leaves out an effect with a `condition` key, independently. Nothing else in the corpus reads effects: result sentences, state and change sentences, and the `observed` mark work from the recorded changes and the replayed states.
14. **The stratified draw** (follow-up 1, Jon's ruling 1 on stage a8). `testsets._stratified` groups a capped set's pairs by true statement in the enumeration order of the statements, puts each statement's pairs in a uniform random order from the set's part of `corpus:tests` (one permutation per statement, in statement order), and takes one pair from each statement in turn, round after round, until the set is full; the kept indices are sorted, so the pairs are written in enumeration order, as in a8. Every statement appears before any appears twice; when there are more statements than the size, the first round takes the first `size` statements in enumeration order. Sets with no more pairs than the size keep every pair, as before.
15. **The statement record** (follow-up 2, Jon's ruling 2 on stage a8) is `statement_record` in the metadata of both items of a causal pair: the true item's causal record with its kind, `{"kind": "effect", "event_type": ..., "role": ..., "fluent": ..., "value": ...}`, beside `statement`. `stats.yaml` is unchanged: `true_statements` already counts the distinct statements.
16. **The specification's as-built notes** are parentheses marked "(As built, stage b1: ...)", one per place in "Conditional effects" where the build departs from or adds to the text, and one on stage a8's acceptance for Jon's ruling 3; the time rule also goes into the guides' README, `WORLD.md`, `CORPUS.md`, and `CLAUDE.md` (a new working rule beside "Tests before done"). The edits are listed below.
17. **The regenerated runs** go to the default folders, and the old folders are moved aside with the suffix `_pre_b1`, as stage a8 did with `_pre_a8` (a run is written in place, so a stale file would otherwise remain). The word forms are not remade: the lexicon is unchanged, and `render` attaches the a8 word-form runs.

## Open questions for Jon

1. **The kind of a condition literal** (choice 7) is drawn with an even chance of a static feature and a fluent. The alternative that follows the world's counts (a uniform draw over the 88 symbols of the default world) gives almost no fluent conditions (none in 17 literals on seed 1). Should the split be a setting (for example `event_types.effects.condition_kinds: {feature: 1, fluent: 1}`), or stay fixed?
2. **The share counts drawn effects, not effects** (choice 6): an inherited conditional effect counts once in the draw and many times in the world, so the default world has 31% conditional effects at `conditional_share: 0.2`. Should the share instead be the share of all effects of all event types (which would mean drawing the feature effects' conditions with a lower chance, or drawing conditions per event type and not per feature)?
3. **A never-able holder counts as satisfied** (choice 8): an event type with no able binding has no event, so its conditions are vacuous. The alternative drops the condition from a feature's effect whenever one event type of the branch is never able, which on seed 4 denied the feature's effect any condition.
4. **The condition stays on the effect's record** rather than in the literal table: the Rust runtime evaluates a condition literal directly (a feature from the static facts, a fluent from the state or its rule), as it evaluates a precondition literal. Should conditions and preconditions instead become rules of the matrix form, so that the runtime evaluates nothing but layers?

## Notes for stage b2

What the builder of the world's comparisons and numeric fluents must know about where things stand.

- **Conditions are in place** for Boolean fluents and static features.
